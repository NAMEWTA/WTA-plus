## 实际问题与实现

旧正式入口在缺少 admin-web Nginx 模板时退出1，但四个后端 Docker 上下文已被覆盖。`run-t10-old-stage.py` 在一次性目录真实执行旧 Bash 入口，前后哈希与四个变更路径见 `T-10-old-stage-failure.json`。旧 partial 复制 current 后再覆盖一个目标，manifest仅写当时整体HEAD，无法证明继承产物来源。

新 Bash 正式入口委托标准库Python状态机：完整 build 拒绝 tracked/untracked 脏树，从唯一干净 Git revision 归档到本次临时构建目录；不创建 Git worktree、不复用原工作树 target/dist。后端保持full/core内容门禁，前端安装冻结依赖并串行构建各App。完整版本同时包含JAR、App、六份SQL快照、Nginx/Compose、脚本；schema2逐文件记录sourceRevision/digest/大小/执行位，版本ID包含完整manifest摘要。局部构建只写development，没有可晋升manifest。

build只生成只读版本。stage显式选择ID，先验证全部文件、来源、只读位、ZIP/入口、SQL包络与必需资产，再用一次同目录rename替换current符号链接。固定inode flock拒绝第二操作，失败只清理本次随机临时目录；保留历史及其他stage，旧实体current目录明确拒绝。backup只增加引用，bundle只封装所选版本，不复制运行env和旧Docker上下文。

原子性边界是指针rename：验证/构建/切换前中断保持旧current和context不变；边界之后可见完整新版本，不能承诺切换后进程被SIGKILL仍返回成功。已运行Docker bind mount不会追踪新指针；每条docker-manage命令一次解析固定版本，up显式build/force-recreate，镜像标签带版本ID；运行数据、日志、证书在独立目录。多服务运行时切换不是原子事务。Nacos覆盖文件同样来自固定版本，运行前缀必须匹配构建manifest。
