# T44 A1 logging boundary: fixed-source, read-only review

Source: clean product `e11c1b6f3a4a4a8bdc1746044d65fe8445c0865c`; v5 owned run `16f1337c6c560efe` reached postcheck with all business stages green but `accepted=false` because the raw backend log contained a known credential canary. The raw log was deleted by the runner; this review does not identify which logger leaked. Do not treat the v5 partial HTTP evidence as final acceptance. V6's private safe metadata can establish the exact class and category on the next run.

## Confirmed reachable paths

1. `LogSanitizer.redact` (`wta-common-json/.../LogSanitizer.java:153-166`) only checks property names; it leaves textual values unchanged. The real `GET /resource/oss/{ossId}/download-url` response has `data.url` (`OssService.OssAccessUrl`), and real upload `InitResponse.presignedRequest.url`, `SignPartsResponse.parts[].url`, `ResumeResponse.presignedRequest.url` have signed URLs. `SysLogBodySanitizer:16-18` passes complete JSON to `LogSanitizer.json`; `SysLogFilter:255-264,354-370` adds that body; `SysLogEventWriter:74-87` serializes the event verbatim. The T44 live fixture actually obtains SigV4 URLs containing `X-Amz-Credential`/`X-Amz-Signature`. A property-name-only fix therefore cannot protect arbitrary `url` values or array/string leaves. Apply a log-copy textual-value rule to every JSON leaf: a URL with SigV4 credential/signature/security-token query or another recognized credential query must become `[REDACTED]`; an ordinary URL without such material remains intact. A malformed URI bearing a signature/credential marker must fail closed to `[REDACTED]`, never fall back to the original string. Keep the original HTTP response and signing input unchanged.
2. `OssUploadService.init:64,89` creates and returns a random UUID `uploadToken`; `OssUploadContracts.InitResponse:29-36` and `ResumeResponse:67-79` expose it under `uploadToken`, which is absent from `LogSanitizer.SENSITIVE_NAMES`. It also appears in real upload control routes (`SysOssUploadController:35-61`). `SysLogFilter:237-240,280-305,354-359` derives the path from servletPath/requestURI and logs `LogSanitizer.path`, which currently only hides `/monitor/online/...`. Add `uploadToken` as a sensitive JSON/form name and narrowly hide the token segment for `/resource/oss/uploads/{token}` and its `/parts`, `/parts/sign`, `/complete` variants. Preserve `/resource/oss/uploads` and other ordinary paths; on malformed input within that token route, hide the entire unknown suffix rather than return the raw candidate. `LogAspect:96-98` already stores the Spring route template for `oper_url`, and OSS upload `@Log` annotations disable request/response body persistence, so do not rework those paths to solve the HTTP event leak.
3. Servlet `getRequestURI`/`getServletPath` here do not append the query string; `SysLogFilter:178-188` independently logs `getParameterMap`. Its name check covers `signature`, `credential`, `token`, but not normalized `x-amz-signature`, `x-amz-credential`, `x-amz-security-token` or a parameter named `url` containing a signed URL. The current T44 signed PUT/GET calls go directly to owned MinIO, not through the app's request filter, so this is an adjacent boundary test rather than proof of the observed v5 leak. For the affected app log contract, cover exact credential query names and, if parameter values may be URL-valued in the same scope, apply the same log-copy signed-URL rule to each parameter value. Ordinary `page=2`, business `code`, and normal unsigned URL values must remain legible. Do not redact every URL or every `code` field.
4. The dev profile has `mybatis-plus.sql-log.enabled=true`, `output=console`. `SqlLogInterceptor:97-131,178-222,287-344` reconstructs bound SQL values, includes raw exception messages, then writes via either SLF4J or `System.err` (including chunked output). This is independent of HTTP JSON sanitization. If the v6 safe summary attributes a known canary to SQL_FULL, sanitize the log copy **before** output/chunking in both modes, while preserving mapper ID, timing, SQL operation/shape and original JDBC execution. An exception's class may be logged; an exception message can echo parameters and should not be trusted as safe. Do not change bound SQL or production persistence to solve logging.

`SysLogEventWriter` is a formatting sink, not a second validator; its `write` method copies the supplied event values and emits them. Current `GlobalExceptionHandler.safeRequestUri` uses `LogSanitizer.path`; it will gain the narrow upload-token protection automatically. `OssControllerExceptionHandler` logs a raw URI for lifecycle errors, but its present download route carries a numeric object ID, not this upload token; do not expand this ticket solely on a hypothetical arbitrary path. The current signed URLs are response data and direct MinIO requests, not part of the app servlet path.

## Minimal red/green assertions

- Real-shaped `R.data.url`, `InitResponse.presignedRequest.url`, `SignPartsResponse.parts[].url`, `ResumeResponse.presignedRequest.url`, plus a JSON array containing a signed URL: no access-key/signature/token canary in sanitized HTTP event; original response and request remain byte-equivalent. Ordinary public URL and plain business fields stay visible.
- Malformed signed URL and nested URL containing credential query: fixed `[REDACTED]`, no exception-message fallback. Recognize case-insensitive query keys and decoded JSON string text; do not log full URI when parsing fails.
- Filter request and response event paths hide only the upload-token segment for each real route while the wrapped servlet request still exposes its original path to business code. Query parameters `X-Amz-Signature`/`X-Amz-Credential`/`X-Amz-Security-Token` are hidden, `page` remains.
- SQL logger `console` and `log` modes with a bound credential value, signed URL, and exception message canary emit no canary, including a >8000-character/chunked statement; execution sees original bind values. Retain existing safe numeric/business output assertions.
