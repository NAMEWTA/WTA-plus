# 项目品牌定制与交付

将当前项目交付为用户指定品牌的完整可运行项目。覆盖自有名称、代码和包路径、作者、前后端视觉、技能与文档、运行配置、必要的中间件、本地联调和真实交互验收。

## 激活与输入

只接受用户明确点名 `$project-customization-delivery` 或明确要求使用本 Skill 的调用。读取目录、发现描述或其他 Skill 链接均不算激活；不要把本 Skill 加入自动执行路由。

激活后读取 [输入与工作目录](references/inputs.md)。最少取得：

- 品牌显示名及可用于代码的标识（可从无歧义的英文品牌推导）。
- 可读取的 Logo 文件路径。
- 定制成果的本地持久化根目录。
- 可选中间件服务器；未提供则不部署远程服务。

沿用会话中已提供的参数和授权，只补问真正缺失或有冲突的字段。先检查参数、源目录、目标冲突与可用工具；参数齐全后直接推进已授权实施，不重复索要“是否开始”。人工激活不代表授权推送、发布应用、清空已有数据库或接管其他服务器项目。

## 执行流程

1. **冻结范围与来源。** 读取源/目标适用的 AGENTS、初始化要求及工程规范；发现真实前后端、子模块、构建入口和中间件依赖。建立迁移映射、第三方保留清单、完成标准及工作记录。保留基线、现有改动和回滚证据，按输入约定准备目标目录。
2. **执行整体替换。** 读取 [迁移合同](references/migration.md)，先区分项目自有内容和第三方，再成组重命名目录与引用。更新 Logo、作者、技能、文档、脚本、配置及生成入口。目标目录只保留一套活动实现，不通过旧新前缀并存解决编译问题。
3. **收敛源码门禁。** 运行当前工程实际存在的构建、类型、单元和合同检查；修复本次引入的失败。生成物通过真实生成器刷新。记录存量失败和未运行项，不删除断言、放宽规则或伪造 Git 来源换取通过。
4. **连接或部署中间件。** 仅在提供服务器且任务授权包含部署时读取 [中间件与本地运行](references/infrastructure.md) 并实施；复用已有服务时按授权连接和验证。不提供服务器时继续本地定制与可执行验证，明确联调所缺配置。
5. **真实验收与修复。** 读取 [验收与追踪报告](references/verification.md)。本地运行每个实际 App 和后端，验证 Client、账号、权限和文件链路，再用真实浏览器逐项操作功能。测试发现问题后修复并复测受影响场景。
6. **交付与状态。** 报告和证据持久化到 `<local_root>/temp/relase/`：部署文档写入 `deployment-docs/`，测试、截图和运行日志写入 `tests/`。部署文档是受限文件，可以包含用户要求的服务器地址、持久化地址、账号和密码；测试目录也必须脱敏，不能复制会话 Token、私钥或无关密码。全部范围内必验项通过才宣告完成；存在真实阻塞时写清最后成功步骤、失败、缺失输入及恢复命令，继续可独立推进的工作。用户明确缩小范围后更新验收矩阵，不能自行把未验功能划为通过。

## 全程不变量

- 品牌替换依据所有权与精确映射，不对 `ry` 等短子串或全部 `dromara` 做无边界全局替换。
- 第三方依赖、许可证、版权和真实上游来源保留可验证身份；不要构造并不存在的新品牌上游 URL。
- 已有数据库、缓存序列化类型、凭据加密 AAD、签名协议和客户端会话可能依赖旧标识；先制定实际迁移或隔离策略，不能只改字符串后假定兼容。
- 中间件默认按本项目运行必需项部署；前后端本地调试，不默认远程部署应用、监控栈或示例服务。
- 使用用户指定 Logo，不凭空重绘；不得把验证码、鉴权、私有存储或核心测试关掉以通过验收。
- Skill 本身不携带真实服务器密码、Token、账户或品牌专属路径。运行时生成的受限部署文档可以按用户要求列出实际凭据；Skill 规则、公开迁移报告和测试证据不得内置或泄露这些值。
