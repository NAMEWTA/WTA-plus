# 迁移合同

## 先建映射，再写入

从 POM、package 声明、工作区包、启动类、路由与资源、SQL、Compose、IDE、技能和文档建立自有标识清单。对旧前缀、大小写品牌、类名、npm scope、配置键分别给出精确目标。目标包和路径先做冲突检查。

分清以下内容：

- **自有内容**：模块名、包路径、import、反射类名、MyBatis namespace/type alias、SPI/AutoConfiguration 注册、模板、脚本 class 哨兵、Maven group/artifact/module、npm 包及引用、品牌文案、作者与维护者、技能路径和内链。
- **第三方内容**：例如 `org.dromara.sms4j`、`org.dromara.warm.flow`、Mica、Easy-ES 等，必须以依赖来源和当前源码证明所有权；不能仅凭组织域名归类。记录迁移前后的第三方坐标/版本与 lockfile 包快照并比较。
- **来源与历史**：许可证、第三方版权、真实上游链接、签名/哈希、不可移动基线标签保留真实含义。当前权威文档改为新路径；历史证据的来源身份不虚构。不把证据归档纳入“活动旧实现”统计。

只对准确前缀或符号边界替换。`ry`、`wta` 与 `wta-` 不是同一种匹配：短词误替换可破坏 `dry-run`、密码参数和其他普通单词。不要把 URL、SQL DSL 标记、约束名或加密协议字串当成普通产品文案。

## 同步面

- 移动自有目录与 Java 包后，同步编译/扫描、XML、资源、测试、公开 API 与 SPI 的全部入口。保持既有 HTTP 方法、JSON 字段和模块结构；品牌迁移不是顺带重写业务合同的理由。
- 同步前端所有实际 App、登录页、导航、页标题、i18n、环境文件、存储键、Logo/favicon 和打包资源。识别代码生成输出，修改生成器输入再生成；不要手工编辑生成声明冒充同步成功。
- 作者仅修改自有源码中的既有作者注释和维护元数据，不改 Git 历史、不抹除第三方版权，不为每个无头文件机械新增作者头。
- 更新 AGENTS、SKILL 名称/frontmatter、`agents/openai.yaml`、引用和脚本路径。保留每个 Skill 原有激活策略，尤其本 Skill 的人工激活要求。
- 对推广菜单、外链和 SQL 种子数据检查实际目的地。无新品牌合法地址时移除无业务作用的推广入口，或使用用户提供的有效目标；不生成假的新品牌上游仓库地址。
- 修改初始化 SQL 后同步现有 SQL 合同和源 manifest，保持源标记、顺序与约束一致。manifest 只在明确源变更后显式更新，验证阶段不自动“修正”摘要以掩盖篡改。

## 状态兼容与可恢复性

公开 Java 包重命名会要求使用方重新编译。字符串里的缓存全类名、会话 Client 规则、签名算法标识、加密 AAD、存储配置键、对象 URL 或已有数据可能不能无损替换。按实际状态选择独立新命名空间、重新登录、明确转换迁移或保留兼容协议，不自动丢弃旧数据。

新项目基座可按顺序全量初始化；已有库只能执行审核过的增量变化。不能因为六份 SQL 可重建就向运行库重放。保留变更前备份、摘要、目标身份与仅限本任务的恢复步骤。

## 迁移退出检查

扫描活动路径与文本，分别输出：已迁移、自有残留、第三方/合法来源保留、生成产物待刷新。逐条解释残留，不能用扩大排除范围隐藏失败。构建后检查最终 JAR/前端产物真实类路径、模块集、图标、标题及私密配置排除；目标内不得出现旧新两套活动实现。
