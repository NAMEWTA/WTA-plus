课的隐含假设若反转，合格读者会把哪把枪或哪条走廊认错？

1. **「confirm 跟个人换绑一样，先冻意图再等审核 FINISH。」** 磁盘 `transferBindings` 立刻 `unbindSource`+`insertBinding`。课反例对照 L-036。把假设反转后，Lead 会用本行假闭合 L-036，或反过来拒绝给本 (b) 盖章。
2. **「目标收到短信，所以是目标点确认。」** `verify` 比源 `sourceUserId`。目标会话对不上票 → `CHALLENGE_INVALID`。课反例 10 / 误区 3。
3. **「send 失败会抛 `ENTERPRISE_TRANSFER_NOT_AVAILABLE`。」** 没有这颗码。软失败是 VO 状态字 `NOT_AVAILABLE` + `R.ok`。课误区 4。
4. **「body 里塞 `userId` / `sourceUserId` 能替别人移交。」** SendBo/ConfirmBo 无此字段；unbind 无 body。课开篇。
5. **「字段名 `service` = classic `Controller → Service → Mapper`。」** 架构测试会拆掉 Controller import service。课误区 5。
6. **「`EnterpriseTransferServiceImpl` 是生产分层。」** 只在 test。课误区 14。E2E 证人精度见 Q2。
7. **「UseCase 是空转发，可以删。」** 事务注解除了它没处盖。测试适配器不是生产盖章位置（见 Q2）。
8. **「unbind 会把执照本逻辑删除 / 等于管理员 `revoke`。」** E2E 解绑后 `profile_enterprise.status` 仍 `ACTIVE`。revoke 在 archive。课反例 8 / 误区 8–9。
9. **「验证码存在 `transfer_record` 里。」** 插入无 code 列；哈希在 Redis；明文只进短信参数；`@Log` 不存报文。课误区 10。
10. **「失败次数看 MySQL `failed_attempts`。」** 插入恒 0。五次烧票在 Redis `attempts`。课误区 13。
