课的隐含假设若反转，合格读者会把哪一扇窗或哪台复印机认错？

1. **「矩阵行名 = 口试上限。」** 读者会说角色没有新增/修改窗。磁盘有 `POST /system/role`、`PUT /system/role`。L-015 已对用户行演过同一漏法。本课 `*` 已声明认全表；矩阵未改。
2. **「`ISysPermissionService` 每个请求再查库。」** 三个方法只在 `buildLoginUser`。之后 `@SaCheckPermission` 读 `menuPermission` 复印件。`getRouters` 才现查。把 (b) 性状「读」安在这三个方法上，读者会去 Controller 里找复印机。
3. **「`isSuperAdmin` 就是 `roleKey=superadmin`。」** 前者是 `SUPER_ADMIN_USER_ID`。车间角色闸认复印件字符串。`checkRoleAllowed` **不**挡 `selectAuthUserAll` 把人塞进内置超级管理员角色行 → 对方过车间闸，但没有 `*:*:*`、行过滤不跳过。
4. **「`PUT /system/role` 会换走廊钉子。」** 那是 `PUT /permission`。基础 `edit` 改显示名也整栋踢，但不删 `sys_role_menu`。
5. **「级联 = 循环单删。」** 单删怕孩子、怕钉子，`warn` 停住；级联允许整枝并拆 `sys_role_menu`。Java 两个方法都叫 `remove`。
6. **「停用角色 = 新登录没有这枚 `roleKey`。」** 不能停已分配角色。若闸被绕过，`roleKey` 仍进 `getRolePermission`；菜单 perm 才被 SQL 丢掉。
7. **「改菜单和改角色权限同一时刻踢。」** 角色踢在事务外 Controller；菜单踢在事务内 Service。读者用角色那则单测去套菜单会说错失败回滚。

问：读完后仍说不出的，是不是窗的名字，而是 **矩阵漏的 `add`/`edit` 算不算本格、三枪是写快照还是读快照、以及两口钟/两种踢的调用栈**？
