# 通知供应商配置

在管理端「通知中心 → 通知配置」配置账号，再将账号绑定到需要的通知场景。新环境包含以下停用账号；已有环境可点「新增账号」选择相同预设，无须重放初始化 SQL。

| 预设 | 已填参数 | 需要填写 |
|---|---|---|
| 腾讯云短信 `sms-tencent` | 厂商 `tencent` | SecretId、SecretKey、已审核短信签名、SMS SDK AppID |
| 阿里云短信 `sms-alibaba` | 厂商 `alibaba` | AccessKey ID、AccessKey Secret、已审核短信签名 |
| QQ 邮箱 `mail-qq` | `smtp.qq.com:465`，SSL | 完整邮箱用户名、发件人地址、SMTP 授权码 |
| 网易 163 `mail-163` | `smtp.163.com:465`，SSL | 完整邮箱用户名、发件人地址、客户端授权密码 |
| 腾讯企业邮箱 `mail-tencent-enterprise` | `smtp.exmail.qq.com:465`，SSL | 完整邮箱用户名、发件人地址、客户端专用密码 |

腾讯企业邮箱用于企业微信中的邮箱场景；企业微信应用消息或群机器人不属于邮件渠道。邮箱所有者需要先在对应邮箱设置中开通 SMTP；企业邮箱还可能受管理员的客户端访问策略限制。预设没有账号、密码或密钥，默认停用，也不会自动绑定业务场景。

1. 编辑预设账号，填入凭据和必填字段后启用。密钥只写不读，编辑时留空保留已保存的值。每分钟 60 次是本地初始限额，应按账号配额和业务需求调整。
2. 邮件场景已有验证码、身份变更、企业转移、工作流和公告的文案，选择启用的邮箱账号并保存绑定即可使用；可按需调整文案中的声明变量。
3. 短信场景还必须填写供应商控制台审核通过的模板 ID/CODE。阿里云变量映射填供应商参数名；腾讯云变量映射填模板占位的位置 `1`、`2`、`3`……，必须从 1 连续编号、不能重复。模板 ID、签名和 SMS SDK AppID 均属于账号实际资源，预设无法替账号所有者申请。
4. 使用自己的测试收件人完成账号和场景试发，再绑定正式业务。没有绑定或账号停用时该渠道会明确失败，不会自动选用其他账号。

账号的渠道、配置标识和已选择的短信厂商创建后不可替换；切换厂商请新增账号。删除账号会隐藏账号并保留配置标识，不能再用同一标识创建新账号，以免历史回执误归属。

发送成功表示供应商或 SMTP 服务器已受理。阿里云保存 `BizId`，腾讯云保存该收件人的 `SerialNo`；请求级 `RequestId` 不作为送达关联号。成功响应缺少可确认的流水号时保留“已受理”，不会仅因缺 ID 自动重复发送。SMTP 受理不等于已投递或已读。

厂商原生回执的字段、认证和确认响应必须按各自协议接入。现有 `X-Notify-Signature` 是本系统的自定义 HMAC 格式，腾讯/阿里短信原生推送不会自动携带它；不得把该地址直接当作已支持的厂商回调。SMTP 预设不提供 HTTP 送达事件。

腾讯、阿里的已受理短信会自动查询送达状态，复用账号密钥，无须另外设置公网回调地址或回调密钥。腾讯账号需允许 `sms:DescribeSendRecordList`，阿里账号需允许 `dysms:QuerySendDetails`；账号停用或删除后停止查询。不同云账号请使用新的配置标识，已有配置的凭据更新用于同一云账号的密钥轮换。

首次核对最早在受理一分钟后进行；每个应用节点每轮最多查询一条，间隔五秒，同一投递预约十五分钟后才能再次领取。数据库预约避免多个节点同时领取同一个到期快照，进程退出后可到期恢复。跨节点总请求量仍需按实际部署规模和厂商额度评估；这是初始调度参数，不是生产吞吐保证。

自动核对持续至受理后 71 小时，超过窗口、没有流水号、供应商查询失败或关联不明确时保留“已受理”，不会当作送达或重新发送。腾讯完整扫描最多 1000 条号码记录，超过范围拒绝确认；阿里按 BizId、号码及发送日核对唯一记录。可通过供应商控制台核实仍未确认的记录。查询窗口与供应商重试期限无关，已经保存的去重记录不自动删除。依据：[腾讯发送记录查询](https://cloud.tencent.com/document/api/382/137245)、[阿里发送详情查询](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-querysenddetails)。

官方参考：[腾讯云 SMTP 配置](https://intl.cloud.tencent.com/zh/document/product/1266/71700)、[网易客户端设置](https://help.mail.126.com/faqDetail.do?code=d7a5dc8471cd0c0e8b4b8f4f8e49998b374173cfe9171305fa1ce630d7f67ac25c12dcb3d46222b6)、[腾讯云发送短信](https://cloud.tencent.com/document/api/382/38778)、[阿里云发送短信](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms)、[腾讯云状态回执](https://cloud.tencent.com/document/product/382/59178)、[阿里云状态回执](https://help.aliyun.com/zh/sms/developer-reference/smsreport-http)。


## 自定义受信回执接入

`POST /notify/callback/{SMS|MAIL}` 仅供已完成来源验证的受信适配器使用；预设账号的发送不需要配置此接口。使用 `Content-Type: application/json`，`X-Notify-Signature` 为独立 `notify.callback-secret` 对完整 UTF-8 正文计算的 HMAC-SHA256 十六进制值。未配置密钥时拒绝全部请求，生产接入应使用 HTTPS。

正文包含字符串 `eventId`、`timestamp`（ISO Instant）、`providerKey`（账号配置标识）、`providerMessageId`、`status`，可选字符串 `target`。其他字段和非字符串值拒绝。`eventId` 在一个渠道账号内必须唯一，每个收件人的状态事件单独编号；同消息多收件人时必须填写准确的 `target`。状态支持 `ACCEPTED`、`DELIVERED`、`UNDELIVERABLE`、`FAILED`、`UNKNOWN`，终态不被迟到的低等级状态覆盖。

`eventId` 不得以 `native-sms:` 开头，该前缀保留给内部已鉴权状态查询；原生核对和自定义回执使用独立事件身份，共享持久事务和单向状态规则。

签名时间允许当前时间前后 5 分钟。生产方重试时保留事件编号与业务事实，可更新时间戳并对新的完整原文重签。渠道和状态统一为大写，其余业务字符串必须保持一致；更换目标、消息号或状态必须使用新事件编号。数据库凭据不自动过期，事务回滚不消费事件，重启不会忘记已处理事件。

只有 HTTP 200 且 JSON 响应 `code=200` 才是已提交确认（含相同事实重复）；项目通用错误处理可能返回 HTTP 200 的失败响应，不能仅凭传输状态确认。401 表示验签失败，400 表示正文或时间戳错误，409 表示事件编号被不同事实复用，422 表示非法参数或关联不唯一。503 表示发送结果尚未关联或业务写入暂时失败；500/503、连接中断或未收到确认时，可按相同事实重新签名重试。不要把腾讯/阿里原生回调地址直接配置到此入口，也不要把 SMTP 受理转换成 `DELIVERED`。

回执正文可能包含精确收件地址，HTTP 和操作日志只保留请求元数据及脱敏摘要；业务验签仍读取完整原文。
