- difficulty: high

课的隐含假设若反转，合格读者会把哪扇窗的柜子认错？

1. **「矩阵 (b) 写在 `AuthController.login` 上，所以这个方法体里有写会话。」** 方法体过闸后只调 `IAuthStrategy.login`。`StpUtil.login` + token-session `"loginUser"` 在 `LoginHelper.login`。读者按格子名找 Controller 里的 `login(` 写入，找不到，会以为课讲错，或反过来把策略写入算成门卫自己干的。
2. **「`@SaIgnore` = 六扇都匿名可改别人的账号。」** callback / unlock 自己 `checkLogin`。binding **确实**匿名。把贴纸窗和路条窗合成「社交都要登录」或「社交都不用登录」，两扇都错。
3. **「缺 Client 一律 `R.fail`。」** 只对 login（以及 register **服务抛异常**，不是 Controller `R.fail`）成立。context 缺 Client 是 `R.ok` + 关旗。前端 `parseClientAuthContext` 抛错不能口述成后端 `fail`。
4. **「注册成功 = 已登录；事务失败 = 所有柜子回滚。」** 成功无 `access_token`。验证码失败已删 Redis、可能已记 `LOGIN_FAIL`，用户表仍空。读者会把「不落半用户」说成「失败路径零存储」。
5. **「`social/callback` 成功 = 插入绑定；失败 = 已绑定。」** 他人已占 `authId` 才抛。本人同平台已有行则更新。把 callback 当登录会撞 `checkLogin`；把更新当「已经绑定所以失败」会误报。
6. **「grantType 用列表成员匹配，错种类一定是 `auth.grant.type.error`。」** 子串先过门，Bean 名再挡一层，文案变成「授权类型不正确!」。短针（`pass`、`sms` 的前缀）是反例。
7. **「logout 没带票应 401；带票失败则会话还在。」** 当前实现信封成功；`finally` 仍 `StpUtil.logout`。`loginUser==null` 时 try 里 `return`，**finally 照样撕柜**。
8. **「OBJ-11 的五扇 = 矩阵六名。」** 读者按 OBJ 口述可以不提 binding；按 chain 漏 binding 则本格 (a) 不算满。L-012 已经按五扇引用本课。

问：读完后仍说不出的，是不是「六扇窗的名字」，而是 **会话到底是谁写的、注册失败时 Redis 动不动、callback 成功是插入还是更新、binding 算不算 OBJ-11**？
