## Compatibility and deployment limitation

The new public common method is additive; old relative cache methods and wta-api notification command signatures remain. Only `NotifyDispatchResultUseCase` implements the internal result port, and the public Worker calls dispatch with the claimed object, so the transient origin field reaches the gate. `@TableField(exist=false)` and `@JsonIgnore` prevent schema/JSON drift. Two Skill references now describe the source behavior; old history was retained in a separate disposition record rather than rewritten.

The provenance marker is safe only when **old Workers are stopped before new marker-bearing jobs are created**. Old code could move a crashed PROCESSING task back to READY while leaving the marker; a mixed-version Worker rollout would erase the new code's proof that a READY task has never reached Provider. The writer's handoff explicitly states this rollout condition. It is a deployment prerequisite to record and verify, not a claim that this static C1 review tested a rolling upgrade or production data. No historical task was silently rewritten; a legacy READY/no-marker task that reaches its deadline remains conservative UNKNOWN, while an unexpired one retains T37/T38 retry semantics.
