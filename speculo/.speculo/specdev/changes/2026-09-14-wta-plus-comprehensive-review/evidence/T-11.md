## HTTPS 场景和测试边界

无 Playwright API route mock。构建后的 Admin/Home → 两个随机 loopback HTTPS 端口 → Jetty → Spring MVC DispatcherServlet → 真实 AuthController、SysRegisterService、PasswordPolicyService、GlobalExceptionHandler 和 Repeatable/SysLog 过滤器。

六个浏览器场景：两 App 各自注册后登录/刷新；两 App 各自错误密码拒绝且不生成本地 session；Admin 导出七个包含高位/零值的二进制字节与 JSON 下载错误/遮罩清理；未知 Client、非法注册 DTO 和弱密码拒绝。当前普通二进制导出入口属于 Admin；Home 无此导出页，未虚构其 UI。共享 Axios 的 blob/arraybuffer 回归覆盖两 App 所用传输层。

Java 端另断言真实注册服务写给存储端的是 BCrypt hash、登录域 grant 两次、非法注册未新增用户、所有请求保持 HTTPS/无旧 header、审计无密码/响应 token。持久化、密码 grant/token 签发、验证码、菜单、导出内容是显式 fixture；没有声称验证了生产 System 权限过滤器、数据库注册事务或全应用启动。浏览器观察器只在真实 XHR 收到时保存状态码，用于跨 Home 整页导航验证 JSON 解析，不保存 token/password，也不拦截响应。

该夹具无 Docker/真实业务库，临时 TLS/Jetty/Chrome 进程在 finally 关闭；证书仅 @TempDir 生命周期。默认 Maven 的新 HTTPS 用例需显式 property，独立运行已验证 0 skip。

## 失败历史与修复

- 首次生产 build 被架构检查器强制要求已退役 catalog 拦截；先登记两个检查器路径，再同步事实，终端纯度负向用例保留。
- 第二次 build 发现新增 Axios 测试直接访问 unknown.cause；修复类型断言，第三次生产构建通过。
- 前三次 HTTPS Java 集成退出 1：前两次 Home 注册响应体、第三次 Home 登录响应体在整页导航后无法通过 Chrome DevTools 读取。共同原因是测试观察时机，未发现服务拒绝正常操作。第二次尝试提前 Promise 读取仍失败；第三次保留注册的页面/存储证据后暴露同一登录问题。最终改为浏览器 XHR readyState=4 时解析并仅记录 code，仍通过真实网络、真实服务及成功后 session/页面/存储断言验收。第四次六场景全部通过。所有失败 JSON/log 保留，没有关闭测试或重试掩盖失败。

## 同批切换与恢复方案（待发布授权）

1. 获得后续提交/发布授权后，从同一干净 source revision 生成包含两 App、后端和配置的不可变版本；使用 T-10 manifest/digest 校验，不从本 dirty 工作树伪造可发布版本。
2. 固定当前完整旧版本作为恢复输入。在业务入口暂时隔离流量，停止新会话/请求进入；完成旧请求排空后，同批更新前端静态服务与后端实例，清除边缘旧 HTML 缓存并要求客户端重新载入。禁止旧前端与新后端混流，不增加双协议兼容。
3. 流量恢复前，通过同一固定版本验证登录、注册、Client 拒绝、下载、错误和 health；再放开流量。T-10 的 current 指针原子替换不等于多个容器原子更新。
4. 若任一步失败，继续隔离流量，将所有相关服务整体恢复到预先固定且校验通过的旧版本，再验证后恢复流量。不能只回退前端或后端。旧版本本身仍有旧协议风险，恢复仅为整体一致性措施；本次没有执行该发布流程。
