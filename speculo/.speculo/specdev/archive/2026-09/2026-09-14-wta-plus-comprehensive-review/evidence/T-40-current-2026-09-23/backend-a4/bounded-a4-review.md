## Test construction and contracts

- **The lock test exercises an actual SQL row lock, beyond thread sequencing** (`NotifyNoticeRetractionIntegrationTest.java:575-644`). Retraction enters the real `lockNoticeIntent` DAO call, which executes `SELECT ... FOR UPDATE` (`NotifyNotificationDao.java:99-103`), then pauses while its `@DSTransactional` use case remains open. A second transaction calls the real `lockIntent` DAO (`NotifyNotificationDao.java:36-42`) through the result port. The test records distinct JDBC `connection_id()` values, observes that the second call does not return while the first owns the row, releases the first transaction, then requires the worker gate to return false and checks persisted RETRACTED metadata, zero message/recipient/attempt/provider calls, CANCELLED Delivery and DONE Outbox. The fixture uses one routing DataSource with an eight-connection pool for both JdbcTemplate and MyBatis (`NotifyAtomicResultIntegrationTest.java:98-152`). The 250-ms negative wait is a bounded scheduling observation, not a direct server lock-wait metric, but the real `FOR UPDATE`, distinct connection assertion, post-release completion and persisted outcome together make it materially stronger than a latch-only order test. It does not establish every possible scheduling interleaving.
- **External I/O after the grant is preserved** (`NotifyNoticeRetractionIntegrationTest.java:488-540`). The provider mock starts only after the dispatcher completes its pre-send gate; it asserts no dynamic DB transaction is open, blocks while retract commits, then returns ACCEPTED, OUTCOME_UNKNOWN, or UNSENT_TERMINAL. Each run requires exactly one provider call, matching Delivery and Attempt status, one Attempt, RETRACTED metadata and correct DONE/WAITING_RECEIPT Outbox. This validates that a late retract does not replace an actual post-gate result with a fabricated cancellation. It uses a typed provider mock, so it does not verify an actual SMTP remote outcome.
- **Pre-grant IN_APP, legacy, owner, duplicate and rollback** are distinct cases: `:543-573` gates a worker until after retract and requires no local facts/attempt; `:367-419` makes an audit-only old version UNVERIFIED and an external record without the persisted unsent marker UNKNOWN/WAITING_RECEIPT, both with zero new sends; `:421-445` expires one real lease and proves old token cannot settle the fresh owner's task; `:342-365` keeps the exact duplicate receipt but rejects manual retry and any new wake; `:262-307` injects a late Notice update failure and a duplicate-identity conflict, requiring rollback. Existing `:168-340` still covers positive delivery, narrow fixed seeds, path rollback and independent re-publication V2. None of these assertions weakens the earlier A2 checks.

That is the positive `provenExternalUnsent → noticeUnsent` branch of `NotifyDispatchResultService.java:134-170` and the external side of AC-040's “retract before execution grant: no new request.” `legacyExternalWithoutUnsentProvenance...` tests the opposite UNKNOWN branch; `retractionAfterProviderGate...` tests a call already granted. A targeted real-DB case should publish MAIL-only, retract while the outbox is READY, then claim/dispatch using a provider mock that fails if called; require Provider calls 0, Delivery CANCELLED with `NOTICE_VERSION_RETRACTED`, Outbox DONE, Attempt count 0, and no change to another version. The production predicate currently appears aligned with that expected behavior, so this is an **important test gap**, not a source-level blocker. It can be added within the already registered Admin notify integration-test directory before the final complete candidate.

The ACCEPTED external case asserts status and Attempt but not the exact retained `provider_message_id`; adding that assertion would strengthen evidence that receipt identity survives late retract, although existing provider-result tests cover generic receipt persistence. A4 does not yet prove the frontend own-inbox deep link/permissions, browser behavior, or the complete ticket competition matrix; those remain separate final-candidate exits.
