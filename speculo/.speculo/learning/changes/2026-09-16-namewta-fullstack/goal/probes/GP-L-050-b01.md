- difficulty: high

课的隐含假设若反转，合格读者会把哪扇窗认错？

1. **「Controller 注入了 ProviderCallbackService。」** 注入的是 UseCase。字段名叫 `callbackService` 的是 UseCase 里的 **Port**。课误区 1。
2. **「验签在 Service。」** HMAC 与时间窗在 UseCase；Service 假定这些已经通过。课误区 2。Port javadoc 写明验签和事务由 UseCase 负责。
3. **「登录权限保护这个 URL。」** 类上 `@SaIgnore`。没有 `notify:callback:*` 菜单串。课反例 3。
4. **「每个厂商一把密钥。」** 单一 `notify.callback-secret`。yml 里甚至没有这把键；缺省空串 = 拒绝所有回调。课误区 5 / 边界。
5. **「先把 JSON parse 成对象再序列化去算签名。」** 签名对着到达 UseCase 的原始 `payload` UTF-8 字节。课反例 1。
6. **「假签 / 过期返回 401。」** 本窗是 `R.fail("回调验签失败")` 或乱码过期句。401 是核身邮筒（L-038）和 OpenAPI 样板，不是本 catch。
7. **「成功会回 ACCEPTED/IDEMPOTENT/LATE_IGNORED。」** 本窗成功是空 data 的 `R.ok()`。那三个口吻是核身 outcome。重复 eventId 也是 200 空成功，不换文案。
8. **「重复回调会把聚合再算一遍。」** `seenEvents` 命中、非法迁移、CAS 0 行都不 `refreshAggregate`。课误区 3。
9. **「DELIVERED 之后再来 FAILED 会覆盖。」** 终态集合禁止迁出。课反例 2。对称：**ACCEPTED 不是终态**，`rank(FAILED)=3>2`，ACCEPTED→FAILED **允许**。不要把 ACCEPTED 背成终态。
10. **「`UNKNOWN` 能覆盖 ACCEPTED。」** rank 1 不能压 2。课边界。它也压不住 PENDING（两边都是 1）。它**可以**从 PENDING/UNKNOWN 升到 ACCEPTED/DELIVERED/FAILED。
11. **「status 可以任意字符串。」** 集合外 `回调状态不支持`。入站 `CANCELLED` 也不是合法回调状态（CANCELLED 只出现在「当前已是终态」集合里）。
12. **「时间戳是 epoch 秒。」** 本窗是 `Instant.parse` 的 ISO-8601。epoch 秒是核身信封 `timestampEpochSecond`（L-038）。
13. **「时间窗只拒过去。」** `Math.abs`，未来超过 300 秒同样拒。
14. **「seenEvents 是跨进程事件表。」** 单例上的内存 Map，10 分钟过期；进程重启即忘。多实例并发靠 CAS 的 previousStatus，失败者 0 行且不记 eventId。课类比失效处。
15. **「CAS 0 行也会记 eventId，所以不会重试。」** 0 行 **不**记 seenEvents，同一 eventId 可以再进 Port。非法迁移才会先记再静默。
16. **「找不到投递行也算幂等成功。」** 抛 `未找到对应投递记录`，不记 seenEvents。Worker 还没写下 `providerMessageId` 时门铃会失败关闭。
17. **「回调会改 Outbox 租约 / 把 `WAITING_RECEIPT` 收成 DONE。」** 本窗零 Outbox 写入。`WAITING_RECEIPT` 是 Dispatch 在 delivery=`UNKNOWN` 时给篮子贴的标签（L-052）。课图边界。
18. **「回调会领取新任务 / 打供应商。」** 只升级已有 Delivery。课图边界 / 误区方向。写出盒是 L-051，领取是 L-052，`NotifyClient.send` 是 L-082。
19. **「`channel` 路径大小写必须与库一字不差。」** 查库前 `toUpperCase`。`providerKey` **不会**改大小写。
