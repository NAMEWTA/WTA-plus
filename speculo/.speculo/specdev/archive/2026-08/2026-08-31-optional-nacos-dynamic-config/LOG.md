## LOG-010 — 2026-08-31T23:02:23+08:00 — 配置按即时与重启生效分级
- **设计树节点：** D-008
- **轮次与依赖：** round 2 / D-002
- **状态：** confirmed
- **问题：** Nacos 中的所有 YAML 是否都能在运行中的 Spring 应用里可靠热更新？
- **事实与来源：** 用户采用推荐方案；参考实现通过 ConfigurationPropertiesRebinder 刷新可重绑定对象，但 server.port、数据源连接、条件装配结果和普通 @Value 等启动期状态不能仅靠替换 Environment 安全重建。
- **选项：** 宣称所有 YAML 均即时生效；即时生效配置清单加其余重启生效；所有配置都重启生效。
- **推荐：** 即时生效配置清单加其余重启生效。
- **结论：** Nacos 可以保存一般 YAML，但只有规格明确列出并经测试的配置前缀在当前进程即时生效；其余覆盖在下次启动时生效。
- **原因：** “远程内容已保存”和“Spring 运行时对象已安全重建”是两个不同事实，不能以 Nacos 推送成功替代应用级验证。
- **影响工件：** CONTEXT / ADR / Spec / Ticket
- **约束或不变量：** 管理入口与运行日志必须能区分即时生效和等待重启，禁止笼统承诺所有 YAML 热更新。
- **后续：** D-012、D-013、D-014 决定删除、校验和多实例语义。
- **替代/被替代：** 无

- **问题：** 是否允许数据库密码、第三方密钥等 secret 存入 Nacos？
- **事实与来源：** 用户明确选择允许；部署层环境变量仍保持更高优先级，Nacos 不能覆盖部署者提供的同名强制值。
