# 中间件与本地运行

## 范围与授权

先从运行配置、依赖、业务范围和实际 Compose 识别必要服务，MySQL、Redis、MinIO 是常见组合，不是固定清单。默认前后端本地运行；不要运行 frontend/backend/observability 的 Compose 来代替本地调试，也不要为了所有功能看似完整而自动安装 Nacos、ES、监控或扩展应用。

已有适用部署 Skill 时按实际环境读取相关入口和分支，不能依赖某个品牌固定命名的 Skill 永远存在。会话已有明确目标部署授权就继续准备和实施，不重复请求；只提供连接资料但未授权远程写入时，先做只读审计、渲染可审查候选和备份方案，再取得缺失授权。目标身份或数据归属冲突时停止相关写入，继续独立工作。

## 审计与候选

核对主机指纹、Docker/Compose 能力、服务镜像、占用端口、容器 labels、网络和卷归属。明确远程数据根、Compose project、服务名、地址、数据库、Redis 命名空间和 bucket；不要因服务器已有同品牌服务就自动接管。

生成仅包含已选择中间件的配置，先验证 Compose 和资产摘要。用户指定的数据根是唯一写入边界；目录、容器 labels 和运行时挂载应能互相证明归属。生成私密凭据配置并限制文件权限，不把 SSH 密码、Token 放入命令行日志或 Skill；受限部署文档可按用户要求记录实际凭据，公开摘要和测试证据必须脱敏。

## 初始化与升级

- 已有持久化数据先做备份并核对摘要，按实际版本和 schema 判断是否增量升级。禁止删除卷或重放全量基座来修复未知错误。
- 容器初始化资产要检查真实运行 UID/GID、目录可遍历性、SQL 可读性与 shell hook 执行方式。无执行位脚本可能被入口 source，脚本内 `exit` 会中断后续初始化。
- 健康检查通过不等于全部 SQL 已运行。核对有效 CREATE/DROP 后的表、约束、版本标记及关键种子数据；不能硬编码上次项目的表数量。
- 初始化中断后先确定已执行范围并备份，只补未执行步骤。状态无法辨明或重复出现同一非瞬态失败时停止自动重试，保留日志和精确恢复建议，不反复重启或重导。
- 更新本地初始化资产不代表运行库已更新；记录源文件与运行库分别执行的变更。

## 连接与验证

将新配置写入应用的私密本地配置，并明确外部加载方式；验证最终 JAR 不包含真实本地凭据。前端代理、本地端口、Client 与后端一致。使用锁定的包管理器、Wrapper 与实际构建 profile，不引入无关升级。

验证数据库读写、Redis 认证及隔离 key、MinIO 私有读写、匿名拒绝、签名有效期及真实本地 Origin 的 CORS/ETag。供应商不支持 Bucket CORS API 时，以实际预检和上传验证配置能力，不能仅凭诊断接口断言失败或通过。生命周期清理策略可能删除数据，未经相应授权不能自动开启。

集成测试使用独立 schema、Redis namespace/database 和测试 bucket；会创建/删除同名表的测试串行或分别隔离。测试客户端必须适配真实认证，不能关闭 Redis 密码或借用运行库让测试通过。清理只针对本次创建的测试资源。

运行前后记录目标容器、镜像、状态、挂载与端口。用户要求的服务未 healthy，或实际依赖无法访问时，不写“部署完成”。
