## 1. 实现摘要

新增 `sys_open_api_credential` entity/Mapper/service 和 system 对 common `OpenApiCredentialResolver` SPI 的唯一实现。AppKey 使用 128-bit CSPRNG，AppSecret 使用 256-bit CSPRNG；secret 以 AES-256-GCM 密文、12-byte nonce、16-byte tag 与 `kek_version` 保存，AAD 绑定 owner、AppKey 与 KEK 版本。当前 KEK 从 `openapi.kek`/`openapi.kek-version` 取得，旧版本只从显式 `openapi.keks.<version>` runtime property 读取；缺失、长度错误、tag/AAD 错误均失败关闭且不暴露阶段。

数据库用生成列 `active_owner_user_id` 加唯一索引保证每用户最多一条未删除凭据，AppKey 在含已删除记录的全表范围唯一，因此删除后重建会产生全新 AppKey 且不会复用旧值。表包含完整主键、版本、逻辑删除和七个基础审计字段。DDL/DML 只在 NAMEWTA 文件末尾追加；菜单 component 固定为 `system/openApi/index`，初始化 list/query/add/edit/remove/self 六个权限。

`/system/openApi` 下实现 Spec 锁定的 self/admin GET 与五种 POST action。self owner 只取 `LoginHelper.getUserId()`；admin 在 Sa-Token 权限之外再次确认超级管理员。所有 POST 使用准确 `BusinessType`，并关闭操作日志请求/响应保存；create/reset 响应增加 `Cache-Control: no-store`。只有 `OpenApiCredentialIssued` 包含一次性 secret，摘要、用户列表和查询类型均不含密文或 secret。

所有生命周期写使用 `@DSTransactional`。reset 保留 AppKey，enable/disable/reset/delete 在写后、成功返回前调用 T-05 invalidator；注销失败向上抛出并触发事务回滚。并发 create 最终由数据库唯一约束裁决，失败请求统一返回 409 且不返回第二份 secret。Resolver 每次检查凭据启用/过期与 owner 用户有效性，认证失败统一为 `OpenApiAuthenticationException`。
