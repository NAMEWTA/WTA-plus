1. **「`GET /notify/notice/list` 就是个人收件箱。」** 那是运营公告目录，权限 `notify:notice:list`，读 `NotifyNotice`。课反例 1。本格证人是 `messageRecipients(userId, 500)`。不要为了对照把 L-045 六扇并进本行。
2. **「前端可以传别人的 userId。」** 四扇都没有这个参数。口袋只来自 `LoginHelper.getUserId()`。课反例 2。
3. **「list 也要 `notify:inbox:read` 或菜单上的 `notify:inbox:list`。」** HTTP `list` 只有类上登录。DML C 行 `notify:inbox:list` 管菜单可见，**没有**对应方法注解。课反例 3。有登录、无 `inbox:read` 仍可能看见标题，不能调 read/seen（若权限指令生效）。
4. **「HTTP 200 表示一定改到了行。」** 没有收件行时 `mark` 返回 false，UseCase 丢 void，Controller 仍 `R.ok()`。消息存在但不属于你：看起来像成功。课误区 3。
5. **「seen 和 read 是同一个布尔，顶栏 `readAll` 只补 read。」** `mark` 第三参 false 只保证 seen；true 才尝试写 read。`readAll` 的 SQL 对「seen 空 **或** read 空」的行 **两个时间都写成 now**，已 seen 未 read 的行会把 seenTime **改晚**。不要用单条 `mark` 的幂等去说 `markAll`。
6. **「UseCase 自己查表 / 自己盖事务章。」** DAO 在 Service。本窗 UseCase 无 `@DSTransactional`。课误区 1。不要拿公告 UseCase 的事务章套过来。
7. **「这个 Controller 推 SSE。」** 四个方法都是请求-响应。铃铛是 `persist` 之后的 `pushRealtime`，失败不回滚纸条。课误区 5 / 类比失效。
8. **「收件箱是公告表的个人过滤。」** 数据源是消息表，由 IN_APP persist 写入，intentId 当 messageId。没有投递成功，盒子就是空的。写入链是 L-051/L-052，本课只读。
9. **「监控页的 `readAt` 就是 inbox 的 `readTime`。」** `NotificationDeliveryView.readAt` 来自投递表。两套时间不要混着汇报。L-049 对照一句即可。
10. **「没有测试类就不能盖 (a)。」** 矩阵测试夹具行已 `deferred(test-fixture)`。本窗 Java 侧确实零 Inbox*Test；证人是 Controller/UseCase/Service/DAO/DDL/OpenAPI。不要为了盖章发明测试课。
