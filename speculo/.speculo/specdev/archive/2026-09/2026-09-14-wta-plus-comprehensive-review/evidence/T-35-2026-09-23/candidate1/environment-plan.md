## Prepared driver and exact isolation mechanics

`/tmp/wta-t35/run-notify-sms-integration.py` is opt-in: invocation without `--execute --expected-head <full SHA>` refuses to launch. The Lead should inspect it against the writer's final test before use. It requires fixed HEAD and empty `git status --porcelain --untracked-files=all` both before launch and after cleanup, and records the six public SQL file hashes. It uses only `docker --host unix:///var/run/docker.sock`; no active Docker context or `/srv/ops` service is consulted.

The driver creates `/tmp/wta-t35/runs/<64-bit-run-id>` with mode 0700 (`secrets.token_hex(8)` produces 8 random bytes / 16 hexadecimal characters) and two 0600 private environment files. It generates independent alphanumeric synthetic MySQL root/app passwords in memory. Docker receives root password only through `--env-file`; the app password is used in SQL via stdin and in the Maven subprocess environment, never in argv, shell tracing or result JSON. Maven output is captured in a 0600 raw file, redacted into a separate 0600 private log, and the raw file is removed. No `docker inspect` Config.Env is printed or stored. The private environment files are removed in cleanup.

Only two new containers are used: `mysql:8.4.9` and `redis:8.6.3`, each with exact labels `namewta.test.owner=T-35` and `namewta.test.run=<random>`, full 64-character IDs, and Docker-assigned random `127.0.0.1` ports. The MySQL container auto-creates the unique `namewta_notify_test_<random>` database. Driver streams public SQL `10/20/30/40/50/60` in that order into the **new** database; `60-cde-nacos.sql` alone creates/switches to its own Nacos schema. It asserts 103 application tables and grants a random test user access only to this database. It deliberately does not call `init-mysql-container.sh`: that script requires the fixed `wta-plus` database and MinIO configuration, neither of which T-35 needs. Redis runs without persistence (`--save '' --appendonly no`) and is reachable only via its newly assigned loopback port. No `FLUSH*`, DROP on external instance, shared schema replay, MinIO, or production config is involved.

After Maven, only the exact fresh `TEST-org.namewta.test.notify.NotifySmsDispatchIntegrationTest.xml` is accepted; positive tests, zero skipped/failures/errors, exit 0 and matching source commit are required. Maven runs in its own session/process group with a one-hour failure limit; cleanup checks the group even if its leader has exited, sends TERM then KILL to remaining members, and requires an empty live set. Cleanup then discovers **only** containers matching both labels using `docker ps -aq --no-trunc`, verifies labels via an inspect format restricted to `.Config.Labels`, removes by captured full ID and confirms zero remaining. Cleanup failures, missing captured IDs, open bound ports, missing XML, stale XML, dirty source, or Maven failure all make the result fail; no exception suppresses owned cleanup. The final result JSON records hashes, nonsecret IDs/ports, test counts, exit code and cleanup verdict. It does not claim to test a real SMS vendor.
