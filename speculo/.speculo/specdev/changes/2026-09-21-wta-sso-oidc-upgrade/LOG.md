# WTA SSO 设计日志

## LOG-001 — 2026-09-21 — 内外统一 OIDC
- **设计树节点：** D-001
- **轮次与依赖：** round 1 / 无
- **状态：** confirmed
- **问题：** 内部 App 和外部平台是否使用同一认证核心与协议？
- **事实与来源：** 用户明确“不管是内部用还是外部用……后端 sso 的交互都是一样的”，并指定 OIDC。
- **选项：** 统一 OIDC / 内外两套私有认证。
- **推荐：** 统一 OIDC。
- **结论：** 采用统一 OIDC；不同 Client 的授权配置仍独立。
- **原因：** 符合用户明确要求并支持通用外部接入。
- **影响工件：** CONTEXT / ADR-002 / 后续 Spec
- **约束或不变量：** 不把统一认证等同于共享业务 Token 或全域权限。
- **后续：** 核对协议缺口、参考全文和迁移合同。
- **替代/被替代：** 推进历史 OIDC 延期范围；未改写永久 ADR。

## LOG-002 — 2026-09-21 — 两种界面入口
- **设计树节点：** D-002
- **轮次与依赖：** round 1 / D-001
- **状态：** confirmed
- **问题：** 是否允许 App/第三方构建自定义登录注册界面？
- **事实与来源：** 用户明确允许自定义界面，也可跳转 sso-web。
- **选项：** 仅默认界面 / 默认界面与自定义界面。
- **推荐：** 两种呈现接入统一授权事务。
- **结论：** 两种界面能力均是目标范围；自托管密码界面的信任、会话与凭据边界尚未选择。
- **原因：** 不把 UI 自由度错误缩减为更换 logo，也不把未批准的任意第三方收集密码设为默认。
- **影响工件：** CONTEXT / 设计树 D-005 / 后续 Spec
- **约束或不变量：** 自定义 UI 不能绕过 PKCE、回调白名单、同意和账户准入；不得使用 OAuth password grant。
- **后续：** 取得参考正文后明确 UI 托管与 headless 扩展边界。
- **替代/被替代：** 无。

## LOG-003 — 2026-09-21 — 账户复用和可管理
- **设计树节点：** D-003
- **轮次与依赖：** round 1 / 无
- **状态：** confirmed
- **问题：** SSO 是否建立独立用户目录？
- **事实与来源：** 用户明确复用 sys_*；补充“在对应的 sys 系统用户表等地方显示出来。可以对这个用户进行管理”。
- **选项：** 复用 System / 独立 SSO 用户并同步。
- **推荐：** 复用唯一账户源及统一注册用例。
- **结论：** 不新增账户体系；注册成功写入 sys_user，授权管理员可管理同一账户。
- **原因：** 避免重复开发和生命周期分叉。
- **影响工件：** CONTEXT / ADR-001 / 后续 Spec
- **约束或不变量：** 查看范围遵循数据权限；被管理用户不因注册获得后台管理域。
- **后续：** 设计真实注册到用户管理、停用/改密生效的验收。
- **替代/被替代：** 无。
