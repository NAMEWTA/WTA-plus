课的隐含假设若反转，合格读者会把哪扇窗或哪层楼梯认错？

1. **「Controller 里已经有 Service / Mapper 了。」** 唯一字段是 UseCase。课反例 1。
2. **「矩阵只写了 UseCase，所以没有 `ThirdProviderUseCaseImpl`。」** 磁盘有 `usecase/impl`。把 notify 那种具体类管家套过来会找错文件。
3. **「add 和 save 是两套 Service 方法。」** 门口两扇，管家一条 `save`。课误区 1。
4. **「UseCaseImpl 自己写校验。」** 校验在 Service + `ThirdEndpointSecurity`。课误区 2。
5. **「删除就是 HTTP DELETE / 物理删行。」** 变更用 POST `/{id}/remove`，只把 `delFlag` 写成 `"1"`。课误区 3。
6. **「启用中的供应商可以直接 remove。」** 先撞 `"Disable provider before deleting"`。课反例 2。
7. **「停用了就能删，门还在也行。」** `countActiveEndpoints>0` 仍拒。计数看的是 Endpoint `delFlag=0`，不是 Endpoint status。
8. **「`baseUrl` 写成 `https://api.example.com/v1` 或带 userInfo 也能过。」** `validateBaseUrl` 只要 path 不是空/`/` 就失败。课反例 3。
9. **「改备注可以顺便改门牌号。」** 已存在行改 code 在 `update`/`evict` 之前抛 `"Provider code cannot be changed"`。
10. **「status 查询参数 `"true"` / 空串会变成第三态或保持原值。」** `changeStatus` 非 `"1"` 一律启用。save body 的非法 status 才 `"Provider status is invalid"`。
11. **「add 权限只保护 insert。」** body 自带已存在 `providerId` 时走更新，只要有 `third:provider:add`。课边界。厨房改正也打这扇窗（L-065），会把「只有 edit、没有 add」的人挡在 403。
12. **「DAO 不该碰 Endpoint 表。」** 工作树就是 `ThirdProviderDao` 持 `ThirdEndpointMapper` 做计数。课误区 4。
13. **「改完库网关会自己刷新。」** 必须 `evict`。课误区 5。实现细节（10 分钟 TTL、整命名空间 clear）归 L-064。
14. **「list 只列启用供应商。」** `findActive` 只滤 `delFlag`。停用但不删的行仍在管理列表，才能再启用或删除。课变式 B。
15. **「0 限额表示每秒 0 次。」** 本切片 0=不设；网关 `positive` 才启用。L-064。
