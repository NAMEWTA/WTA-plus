# 账户档案与实名认证架构决策

## ADR-001: 聚合父模块、领域 BOM 与双业务叶子模块

**Status:** accepted
**Source:** LOG-002
**Supersedes:** none

### Context
个人档案和企业档案具有不同的数据、材料与验证规则，但需要在同一账户档案领域下统一版本和装配。

### Decision
在 `ruoyi-modules` 下建立一个聚合父模块；其下建立一个领域 BOM，以及个人和企业两个业务叶子模块。BOM 统一约束两个叶子模块的 `${revision}` 版本。

### Trade-off
两个完全独立的顶层模块边界更强，但会重复版本与装配治理；单一叶子模块更少 POM，却会把两套实体、流程和权限耦合在一起。

### Consequences
个人和企业实现可以独立演进，但聚合 POM、BOM、根依赖管理和 ruoyi-admin 装配必须保持一致。正式 artifactId 等待 D-001 决定。

### Verification / Migration
Maven reactor 同时识别聚合模块、BOM 和两个叶子模块；根级完整与 core bundle 对模块装配结果给出显式断言。

## ADR-002: 档案业务通过公开 API 接入现有工作流

**Status:** accepted
**Source:** LOG-003
**Supersedes:** none

### Context
CDE 参考实现使用业务模块内部审核接口；当前项目已有 ruoyi-workflow，并明确禁止其他业务模块依赖其内部服务或工作流引擎类型。

### Decision
个人和企业认证审核统一由 ruoyi-workflow 承载。两个业务叶子模块只依赖 ruoyi-api，注入 WorkflowService，以认证申请主键作为 businessId，并通过精确 flowCode 的流程事件更新业务状态和绑定。

### Trade-off
业务模块自建审核状态机更直接，但会产生第二套待办、权限和流程生命周期；直接依赖 ruoyi-workflow 实现可少写适配，却破坏跨模块边界。

### Consequences
流程任务和实例留在 workflow，档案申请、材料和有效绑定留在档案模块。流程定义必须在运行环境发布；工作流禁用时的装配与失败策略仍需后续设计节点决定。

### Verification / Migration
构建时两个业务叶子模块的 POM 不包含 ruoyi-workflow 依赖；测试覆盖先落库后启动、重复提交、流程终态回写、失败回滚和禁用工作流装配行为。

## ADR-003: 不可变认证申请快照审核后发布档案

**Status:** accepted
**Source:** LOG-008
**Supersedes:** none

### Context
账户可能在已经存在有效档案和绑定时重新提交认证。若直接修改档案主体，待审、驳回或终止的资料会污染当前认证事实。

### Decision
个人和企业领域均分离档案主体、不可变认证申请快照、材料引用和有效绑定。提交时冻结申请字段与材料；只有流程确认完成后才原子发布为有效档案版本并建立或切换绑定。

### Trade-off
单表状态字段实现更少，但无法可靠表达当前有效版本与历史待审版本；快照模型增加表和映射成本，换取可审计发布和无污染重认证。

### Consequences
列表和业务资格查询以有效档案/绑定为准；审核详情以申请快照为准；材料必须关联具体申请版本。发布状态机仍由 D-016 收敛。

### Verification / Migration
测试覆盖首次认证、已有有效档案时重认证、驳回、撤销、并发提交和发布失败回滚。

## ADR-004: 认证供应商采用策略 SPI

**Status:** accepted
**Source:** LOG-006
**Supersedes:** none

### Context
当前采用材料人工复核，但未来可能同时接入支付宝、微信、微警等多个个人或企业认证供应商。供应商协议、凭据、回调和结果字段会持续变化。

### Decision
个人和企业认证分别定义稳定的验证供应商 SPI，通过 providerCode 注册策略实现；人工复核作为默认策略。档案核心只接收规范化验证结果和证据引用，不依赖具体供应商 SDK 类型。

### Trade-off
直接在应用服务中调用单一 SDK 更快，但新增或替换供应商会污染状态机和领域模型；策略 SPI 增加注册、配置与错误映射成本。

### Consequences
供应商实现可独立扩展，申请需记录 providerCode、尝试和规范化结果。一次申请固定一个已启用供应商且不自动降级或组合；供应商结果只作为审核证据，不能直接发布档案。回调幂等规则等待 D-030 决定。

### Verification / Migration
使用人工与测试供应商验证策略选择、未知/禁用 provider、失败映射、重复回调和供应商专属字段不泄漏到公共 API。

## ADR-005: 首期证件字段明文存储

**Status:** accepted
**Source:** LOG-011
**Supersedes:** none

### Context
个人和企业认证需要保存身份证号、法人证件号等高敏感字段。加密会提高密钥治理、查询和迁移复杂度，用户选择首期先明文存储。

### Decision
首期结构化证件字段以明文写入数据库，不增加字段加密或独立指纹列。

### Trade-off
明文便于查询、判重和运营排障，但数据库、备份、只读副本和运维账号泄露时会直接暴露证件信息；后续改为加密需要数据迁移和唯一索引重建。

### Consequences
取得相应权限的管理用户可查看明文全量字段，首期不提供响应脱敏视图；材料仍需独立鉴权和 OSS 引用归属校验，日志、异常和前端持久缓存不得记录敏感内容。明文存储与明文响应风险必须进入 Spec 和验收报告。

### Verification / Migration
SQL 与 entity 明确字段长度和唯一索引；安全测试确认无权限接口、操作日志和错误消息不泄露证件信息，并确认有权限列表与详情按合同返回全量字段。

## ADR-006: 权限内全量查看且认证历史只逻辑保留

**Status:** accepted
**Source:** LOG-019, LOG-020
**Supersedes:** none

### Context
个人和企业档案包含明文证件字段与高敏感材料。用户要求运营人员取得相应权限后可查看全量信息，不叠加部门数据权限，并要求解绑、注销、驳回后仍可恢复或重新绑定。

### Decision
个人和企业管理接口按功能权限授权平台全量数据，不使用部门数据权限，也不对有权响应脱敏。申请、档案版本、绑定历史与材料引用只允许逻辑状态变化，不提供物理删除业务入口。

### Trade-off
该方案便于人工复核和历史恢复，但显著扩大明文数据的可见范围；它依赖精确权限配置、访问审计和日志约束降低风险，无法降低数据库或有权账号泄露造成的直接暴露。

### Consequences
后端必须逐接口鉴权，材料预览下载不得依赖前端隐藏。权限粒度由 D-029 决定；所有列表导出、日志与错误处理必须作为敏感数据测试面。

### Verification / Migration
测试覆盖无权限拒绝、有权限全量查询、跨部门全量查询、材料鉴权、日志无敏感值，以及所有注销/解绑/驳回路径不存在物理 DELETE。

## ADR-007: workflow 审核与管理员覆盖双通道

**Status:** accepted
**Source:** LOG-021
**Supersedes:** none

### Context
常规认证由两套 workflow 完成人工审核，但运营后台还需要应急直接审批、核心字段修订和档案状态处置能力。直接操作若覆盖历史申请或遗留活动流程，会破坏审计链与状态一致性。

### Decision
保留 workflow 作为常规审核通道，同时提供独立权限保护的管理员覆盖命令。覆盖命令必须记录操作者、原因、来源与变更内容，不物理删除任何记录，也不得改写不可变认证申请快照。

### Trade-off
双通道提高运营纠错能力，也增加流程事件竞态、权限误配和历史版本建模成本。只允许 workflow 更简单，但不满足明确的直接处置需求。

### Consequences
管理员字段修订创建 ADMIN_OVERRIDE 档案版本；活动流程通过公开门面终止；档案版本与绑定分别维护状态；权限按可完整完成的业务能力划分。任何直接修改都不得成为无审计的数据库覆盖。

### Verification / Migration
测试覆盖管理员直接通过/拒绝、并发流程回调、字段修订历史、状态恢复、缺少独立权限拒绝和不存在物理删除。

## ADR-008: 工作流能力可选装配且提交失败关闭

**Status:** accepted
**Source:** LOG-022
**Supersedes:** none

### Context
WorkflowService 实现由 ruoyi-workflow 条件装配提供。若业务模块强制注入，工作流禁用会使档案查询和草稿等非提交流程也无法启动。

### Decision
档案模块通过可选门面获取 WorkflowService。工作流禁用、Bean 缺失或流程未发布时，查询与草稿能力保持可用；提交认证明确失败，并保证本地申请不进入 waiting 且不建立绑定。

### Trade-off
可选装配需要在应用服务中显式处理能力缺失和流程启动失败，但避免把整个档案模块的可用性绑定到审核引擎。

### Consequences
提交流程必须设计先后顺序、事务补偿和稳定错误码；健康检查可暴露流程可用性，但不能用静默降级把申请留在伪待审状态。

### Verification / Migration
分别在 workflow 启用、禁用、Bean 缺失、flowCode 未发布和启动异常场景验证应用启动、草稿保存、提交失败与数据库状态。

## ADR-009: 企业负责人可自助即时解绑与转移

**Status:** accepted
**Source:** LOG-024, LOG-030
**Supersedes:** none

### Context
企业首期只有一个认证负责人，该负责人可能不是法定代表人。用户要求负责人无需管理员或新工作流即可主动退出或把控制权交给另一个已注册且完成个人实名认证的账户。

### Decision
当前 active 企业负责人可以自助即时解绑，也可以输入目标账户的实名姓名、认证证件号后四位和绑定手机号，完成发送到目标绑定手机的专用验证码校验后执行原子转移。转移不进入 workflow、不需要管理员批准；法定代表人信息不用于自动匹配系统账户。

### Trade-off
即时转移操作简单，实名三要素与目标手机验证码可以降低误选风险，但仍必须对目标资格、当前负责人身份、并发状态和审计历史做强校验。独立登录确认更强，但会增加目标账户操作步骤。

### Consequences
后端需要独立的本人解绑、转移挑战发送与转移确认命令，只允许当前负责人调用。挑战使用 6 位验证码、5 分钟有效期、60 秒发送间隔、5 次错误上限，并绑定完整转移上下文；本人解绑后不能自助恢复，只能重新认证或由管理员指定绑定。

### Verification / Migration
测试覆盖非负责人拒绝、实名三要素不匹配、验证码错误/过期、目标不存在/未实名、重复提交、并发转移、解绑与转移历史、无管理员权限但本人合法操作，以及任何路径不物理删除绑定。

## ADR-010: 档案版本、绑定状态与管理员修订分离

**Status:** superseded
**Source:** LOG-023, LOG-028
**Supersedes:** none

### Context
管理员可以直接修订认证核心字段和改变档案状态，但历史申请快照必须不可变，解绑或注销后又必须能够恢复。

### Decision
管理员核心字段修改创建带来源和差异审计的 ADMIN_OVERRIDE 档案版本并原子替换 current。档案版本状态为 current/superseded/revoked；绑定状态为 active/suspended/unbound；状态处置和恢复均追加历史事件。

### Trade-off
版本与绑定分离会增加表和事务复杂度，但避免一个状态字段同时承担内容版本、认证资格和账户关系语义，也避免直接覆盖丢失历史。

### Consequences
申请快照、档案版本和绑定关系拥有各自生命周期；查询当前资格必须同时检查 current 档案版本和 active 绑定。普通申请人核心字段变化仍通过重新认证。

### Verification / Migration
测试覆盖修订版本切换、旧版本不可变、停用/解绑/注销/恢复、唯一性冲突和事务失败回滚。

## ADR-011: 管理员覆盖通过公开工作流终止合同收口

**Status:** accepted
**Source:** LOG-027
**Supersedes:** none

### Context
管理员可绕过 workflow 直接审批 waiting 申请，但当前 WorkflowService 没有按业务主键终止活动实例的公开能力。删除实例会丢失正确的终止语义，让实例继续运行又会产生迟到决定竞态。

### Decision
在 ruoyi-api 的 WorkflowService 增加按 businessId 终止活动实例并携带原因的引擎中立门面，由 ruoyi-workflow 实现。管理员覆盖命令使用该门面结束流程，并用 ADMIN_OVERRIDE 作为业务最终决定来源。

### Trade-off
扩展公共 API 增加 workflow 模块维护面，但维持业务模块不依赖 IFlw* 或 Warm-Flow 类型，并保存完整流程历史。

### Consequences
终止事件与管理员决定需要幂等、版本守卫和明确失败原子性；迟到流程事件不得覆盖管理员决定。具体竞态协议由 D-037 收敛。

### Verification / Migration
API 兼容测试和集成测试覆盖无实例、活动实例、已终态实例、终止失败、重复终止及终止事件与直接审批并发。

## ADR-012: 权限按完整业务能力分组

**Status:** accepted
**Source:** LOG-029
**Supersedes:** none

### Context
档案查看、材料、workflow 办理、状态处置和管理员覆盖的风险不同，需要细粒度授权；但若把内部读取和校验拆成独立权限，角色即使拥有操作权限也可能无法完成该操作。

### Decision
个人和企业分别公开 apply、query、material、review、manage、override 六类能力权限。每个写命令的权限包含完成该命令所需的内部读取、归属校验与配套动作，不要求额外实现细节权限；前端仅投影后端授权。

### Trade-off
能力包比逐端点权限粗，但能保持角色配置可理解和操作闭合；比单一管理权限细，仍可隔离明文查看、材料和高风险覆盖操作。

### Consequences
review 接口必须能取得审核必需快照与材料，override 能完成流程终止和最终决定，不能在执行中途再因缺少 query/material 等权限失败。权限字符串和接口矩阵由 Spec 固化。

### Verification / Migration
为六类权限建立正反授权矩阵，验证每类已授权操作能够完整完成，未授权高风险命令在进入事务前拒绝。

## ADR-013: 供应商回调由适配器鉴权并在领域层幂等

**Status:** accepted
**Source:** LOG-031
**Supersedes:** none

### Context
不同供应商使用不同签名、时间戳和重试协议，且可能重复、乱序或在申请终态后回调。供应商结果首期只作为审核证据。

### Decision
每个 VerificationProvider 适配器验证其签名和时间窗；领域层以 providerCode 与 providerRequestId 唯一记录验证尝试。同内容重复返回幂等成功，冲突或迟到结果只记录安全审计，不改变申请、档案或绑定。

### Trade-off
适配器承担更多安全协议代码，但避免把供应商字段扩散到领域核心；严格拒绝迟到结果可能需要运营查看审计记录处理供应商异常。

### Consequences
回调 API、签名错误和冲突响应可因 provider 不同而适配，领域状态迁移保持统一。任何回调都不能直接发布档案。

### Verification / Migration
使用测试 provider 覆盖合法、伪造、过期、重复同内容、重复冲突、乱序和终态后回调。

## ADR-014: 跨模块只读消费通过 ProfileService

**Status:** accepted
**Source:** LOG-034
**Supersedes:** none

### Context
其他业务需要判断账户是否具备个人或企业认证资格，但不能依赖 profile 内部表、entity 或管理 HTTP，也不应因此获得敏感证件和材料。

### Decision
在 ruoyi-api 公开引擎与持久化无关的 ProfileService，提供按 userId 单个和批量查询有效个人/企业绑定状态及非敏感主体摘要的合同，由 profile 模块实现。

### Trade-off
公共 DTO 需要长期兼容，但能保持模块边界并集中当前资格判定。直接查表更灵活，却会复制状态和绑定规则。

### Consequences
证件号、材料和申请历史不进入公共模块查询 DTO；需要这些数据的运营场景继续使用受权限保护的 profile HTTP API。

### Verification / Migration
合同测试覆盖个人/企业未认证、active、suspended、unbound、revoked、批量缺失项和敏感字段不暴露。

## ADR-015: 可编辑工作副本与不可变提交快照并存

**Status:** accepted
**Source:** LOG-035
**Supersedes:** none

### Context
申请在 draft、back、cancel 状态允许编辑重提，但审核看到的每一版字段和材料必须保持不可变。

### Decision
认证申请拥有可编辑工作副本；每次 submit 生成递增 submission snapshot 和对应材料引用版本。重提继续使用申请 ID 作为 workflow businessId，但审核和发布精确关联当前提交版本，旧版本永久保留。

### Trade-off
同一申请下增加版本表和当前版本指针，比覆盖单行复杂；换取完整审核证据和连续流程业务标识。

### Consequences
waiting/finish 快照不可写，退回或撤销后的表单只更新工作副本。流程变量、审核详情和最终发布必须携带或解析正确 snapshotVersion。

### Verification / Migration
测试覆盖多次退回重提、每版材料差异、旧版不可改、迟到事件引用旧版本和最终发布版本正确。

## ADR-016: 主动解绑后只能重新认证或由管理员指定

**Status:** accepted
**Source:** LOG-036
**Supersedes:** none

### Context
企业负责人可以主动解除绑定，档案和历史材料仍保留。是否允许原负责人无审核恢复会影响解绑的安全含义。

### Decision
普通账户没有 unbound 绑定恢复命令。原负责人和其他账户都必须重新提交企业认证；具备 enterprise override 权限的管理员可以创建直接指定绑定决定。

### Trade-off
重新认证增加操作成本，但使主动解绑成为明确终止动作；管理员指定保留运营修复能力并承担更高审计要求。

### Consequences
重新绑定创建新的 active 绑定事件，不回写旧绑定。管理员指定仍要求目标正常注册、个人认证 active 且不存在其他 active/suspended 企业绑定，仅免除短信确认。

### Verification / Migration
测试确认本人恢复接口不存在、旧材料保留、重新认证发布新绑定，以及管理员指定具有独立权限和审计。

## ADR-017: 管理员覆盖以决定版本协调工作流终止

**Status:** accepted
**Source:** LOG-037
**Supersedes:** none

### Context
管理员覆盖与 workflow 任务完成可能并发，简单最后写入会产生相反终态、重复发布或活动实例遗留。

### Decision
管理员覆盖先锁定申请并写入递增 decisionVersion 与 override-pending 意图，再终止活动流程。只有终止成功或已无活动实例时才提交 ADMIN_OVERRIDE；流程监听器遇到更高版本或管理员来源时只记录事件，不回写最终状态。

### Trade-off
版本围栏和 pending 状态增加失败恢复复杂度，但提供确定的最终决定顺序。最后写入获胜实现简单但不可证明一致。

### Consequences
终止失败必须使直接审批失败且不发布档案；重试使用同一幂等命令或更高决定版本，不能叠加多个发布结果。

### Verification / Migration
并发测试覆盖任务先完成、覆盖先挂起、终止事件同步回调、终止失败、超时重试和重复管理员命令。

## ADR-018: 首期证件范围限定为大陆及港澳台

**Status:** accepted
**Source:** LOG-032, LOG-038, LOG-041
**Supersedes:** none

### Context
个人认证需要覆盖大陆及港澳台多类证件，曾考虑建设全球国家/地区证件目录，但用户决定其他国家以后再扩展。

### Decision
首期只支持中国大陆、香港、澳门和台湾的当地身份证件、居住证、往来通行证，以及上述地区签发的护照或旅行证件。每类证件拥有明确 code、号码规则和材料规则；负责人转移统一使用当前认证证件号后四位。

### Trade-off
区域固定目录减少全球证件规则、翻译和测试成本，但其他国家账户无法完成首期个人认证。后续扩展需要新增证件 code 与迁移兼容，而不能改写已有 code 含义。

### Consequences
不建设 issuingCountry 全球配置系统，也不改造手机号国际化。护照资料页与身份证正反面分别验证，不能共用必传材料规则。

### Verification / Migration
证件矩阵测试覆盖每个支持 code、签发地区、号码校验、必传材料、有效期和不支持国家拒绝。

## ADR-019: 负责人转移使用业务专用短信挑战

**Status:** accepted
**Source:** LOG-033, LOG-039, LOG-041, LOG-042
**Supersedes:** none

### Context
负责人转移需要确认目标账户身份与手机控制权。现有匿名登录验证码仅按手机号使用全局 captcha key，无法绑定企业、双方账户和单次转移意图。

### Decision
profile 创建专用转移挑战，精确匹配目标实名姓名、认证证件号后四位和当前 system 绑定手机号，通过 NotifyClient 向 UserService 返回的手机号发送 6 位验证码。挑战 5 分钟有效、60 秒限发、最多 5 次错误、成功即消费，并绑定当前负责人、企业、目标账户和 challengeId。

### Trade-off
专用挑战增加 Redis 状态和接口数量，但阻止登录验证码复用、跨企业重放和任意手机号投递。手机号格式与可达性仍受 system 当前合同限制。

### Consequences
发送与确认是两个独立 POST 命令；确认时必须重新校验双方资格和绑定版本，不能只相信发送时快照。操作日志和通知审计不保存验证码、手机号、姓名或证件片段明文，只记录业务标识与结果。

### Verification / Migration
测试覆盖三要素不匹配、模糊响应、发送失败、过期、限频、五次错误、成功消费、重放、绑定变化和并发确认。

## ADR-020: 已挂接材料永久保留且孤立文件仍归 system OSS

**Status:** accepted
**Source:** LOG-045
**Supersedes:** none

### Context
认证材料必须随申请、档案和绑定历史永久可追溯，但上传后从未挂接的文件属于全局 OSS 生命周期，profile 不拥有全局孤立文件治理。

### Decision
任何挂接到工作副本、提交快照或档案版本的 OSS 引用及底层对象均不由 profile 物理删除。未曾挂接的 OSS 对象继续遵守 system OSS 合同和清理策略。

### Trade-off
永久保留会持续占用存储，但满足历史重审和重新绑定要求；保留所有全局上传则会把无关孤立文件错误纳入 profile 责任。

### Consequences
材料关系需要记录 OSS ID、标签、文件大小和挂接来源。所有状态变化、标签停用和版本替换只能改变引用可见状态，不能调用 OSS 删除。

### Verification / Migration
测试覆盖各挂接阶段、驳回/解绑/注销/重提/版本替换和孤立 OSS 不被 profile 接管。

## ADR-021: 管理员可无申请直接建立档案

**Status:** superseded
**Source:** LOG-048
**Supersedes:** none

### Context
除用户申请和 workflow 审核外，运营需要录入存量个人或企业档案，并可直接向账户分配绑定。

### Decision
具备 override 能力的管理员可以无用户申请、无 workflow 从零创建个人或企业档案，也可以在同一业务动作中选择合格账户建立绑定。该通道仍遵守身份键唯一性、每类绑定基数和永久审计要求。

### Trade-off
直建通道提高运营效率，但成为与 workflow 并列的身份事实来源，需要独立来源类型、证据版本和更严格权限。强制先造申请只为复用流程模型，会歪曲真实来源。

### Consequences
ADMIN_CREATE 的字段、材料和不可变证据由 D-051 收敛；管理员入口不得伪造申请人或 workflow 历史。普通用户信用代码预填只减少录入，不自动获得绑定。

### Verification / Migration
测试覆盖个人/企业直建、可选绑定、重复身份键、目标资格、无权限拒绝、审计来源和失败原子性。

## ADR-022: 管理员直建档使用独立不可变来源快照

**Status:** accepted
**Source:** LOG-048, LOG-051
**Supersedes:** ADR-021

### Context
运营需要无用户申请、无 workflow 录入存量档案并可直接绑定账户，但首次身份事实仍必须具备与普通认证等价的字段和材料证据。创建伪申请会错误陈述事实来源，只写当前档案又会丢失首次建档证据。

### Decision
具备对应 override 能力的管理员可以从零创建个人或企业档案并选择合格账户原子绑定。直建必须满足普通首次认证相同的核心字段和必传材料规则，不创建申请或 workflow 实例；系统生成不可变 ADMIN_CREATE 来源快照、材料版本和首个 current 档案版本，并记录管理员、原因和时间。后续核心字段变化创建 ADMIN_OVERRIDE 版本。

### Trade-off
独立来源快照比复用申请表增加一种证据来源类型和查询分支，但能准确表达管理员录入事实并保留完整审计。只保留当前版本实现更简单，却无法证明首次创建时提交了什么材料。

### Consequences
后台个人和企业列表提供独立新建入口；详情必须能区分 USER_SUBMISSION、ADMIN_CREATE 与 ADMIN_OVERRIDE 来源。直建通道继续遵守身份键、绑定基数、目标账户资格和材料永久保留规则，不生成虚假的流程轨迹。

### Verification / Migration
测试覆盖无申请直建、必传材料缺失、来源快照不可变、可选绑定、目标资格、重复身份键、无权限拒绝、失败回滚，以及后续 ADMIN_OVERRIDE 不改写 ADMIN_CREATE 证据。

## ADR-023: 材料目录采用受限节点树和单标签绑定

**Status:** accepted
**Source:** LOG-044, LOG-049, LOG-055
**Supersedes:** none

### Context
个人与企业认证材料既需要运营可维护的分类，也需要稳定标签参与必传规则和历史审计。自由文本无法治理，任意深度或多分类标签会让规则校验、停用和前端选择产生歧义。

### Decision
profile 自有材料目录严格使用个人、企业、通用一级分类，可直接挂标签或增加一层二级分类后挂标签。分类与标签统一为带 nodeType、parentId 的树节点，每个标签只有一个父分类；独立绑定表将每个材料引用绑定到恰好一个启用标签叶子。存在子节点、必传规则或材料引用的节点禁止物理删除，已引用标签只可停用，历史材料保存标签名称快照。

### Trade-off
受限层级和单归属比任意树、多对多标签更少自由度，但能让必传规则、适用范围和树表交互保持确定。分类与标签共用节点表减少目录表数量，但需要通过 nodeType 与层级校验阻止非法结构。

### Consequences
后端必须在写入事务中校验父节点类型、深度、适用域和标签状态；申请端只能选择叶子标签。管理端复用树表交互范式但不依赖 system 菜单或部门模型，材料快照不能只依赖当前标签名称。

### Verification / Migration
测试覆盖合法三层路径、一级直挂标签、非法深度、分类节点不可选、多父归属拒绝、引用后删除拒绝、停用标签不可新选以及历史名称快照不变。

## ADR-024: 注销终结旧档案并以新档案重新认证

**Status:** accepted
**Source:** LOG-023, LOG-028, LOG-052, LOG-057
**Supersedes:** ADR-010

### Context
档案内容版本、账户绑定和主体注销是不同生命周期。旧方案允许 revoked 后恢复原档案，但用户明确注销是逻辑删除，再次认证必须新建；同时历史档案、材料和绑定又不能物理删除。

### Decision
档案内容继续以 current/superseded 版本及 ADMIN_OVERRIDE 来源记录变化，绑定继续以 active/suspended/unbound 及追加事件记录关系变化。个人或企业档案注销时逻辑终结旧主体并解除其有效绑定，旧档案不能恢复、编辑或重新绑定；再次认证创建全新档案 ID、申请快照和材料版本，并以 previousProfileId 关联前一档案。身份键唯一性只覆盖未注销档案和进行中申请。

### Trade-off
新建档案会让同一法律身份在历史中拥有多个档案 ID，并增加前后继查询与活动唯一约束；换取清晰的注销终态和不可篡改历史。恢复原档案更简单，但会削弱注销语义并混合不同时期的身份事实。

### Consequences
跨模块 ProfileService 只把未注销 current 档案与 active 绑定视为有效。数据库必须允许多个已注销历史记录共享身份键，同时强制最多一个未注销档案和一个进行中申请；后台详情需要沿 previousProfileId 查看历史链。解绑与暂停仍只作用于绑定，不等同于档案注销。

### Verification / Migration
测试覆盖个人和企业注销、新建 ID、前后继链、旧档案不可恢复/编辑/绑定、同身份并发重建唯一性、旧材料永久保留，以及跨模块有效状态不误认历史档案。

## ADR-025: 必传材料规则引用受保护标签编码

**Status:** accepted
**Source:** LOG-014, LOG-015, LOG-025, LOG-055, LOG-060
**Supersedes:** none

### Context
不同个人证件和企业办理身份具有不同必传材料，材料目录名称和排序又需要运营调整。如果规则依赖显示名称或完全可删除的动态标签，改名、停用和目录维护会悄然解除认证要求。

### Decision
个人证件类型与企业办理规则只引用稳定 materialTagCode。首期必传标签由 DML 预置并标记 systemRequired；管理员可修改显示名称和排序，但不能修改 code、停用或删除。普通提交与 ADMIN_CREATE 使用同一 profileType、documentType 和办理身份材料矩阵，每个必传标签至少存在一份合规材料。

### Trade-off
受保护标签减少运营完全自由配置的能力，并要求新增证件类型时同步维护 DML、规则和测试；换取不会因目录操作破坏认证底线的稳定合同。全部写死为 Java 枚举更简单，但无法复用可运营目录和历史标签快照。

### Consequences
标签管理写命令必须识别 systemRequired 并失败关闭；规则校验按 code 而非节点 ID 或显示名称。扩展标签可以正常增停，但不会自动参与必传判断；同一必传标签允许多份材料，当前集合总数仍最多十份。

### Verification / Migration
证件材料矩阵测试覆盖缺失必传标签、重复同标签、错误适用域、系统标签改码/停用/删除拒绝、显示名称修改不影响规则，以及普通提交与 ADMIN_CREATE 校验一致。

## ADR-026: 普通绑定探测采用不披露响应

**Status:** accepted
**Source:** LOG-048, LOG-052, LOG-063, LOG-064
**Supersedes:** none

### Context
个人证件信息和统一社会信用代码既用于提交认证，也可能命中系统已有档案。若普通绑定接口回填旧主体字段，它会成为无需档案查看权限的数据枚举通道，并让新申请错误复用旧证据。

### Decision
个人和企业普通绑定探测只返回当前身份是否已被其他账户绑定的最小状态，不返回或预填个人姓名、企业名称、法定代表人、地址、材料、历史负责人及其他档案字段。申请人必须自行填写完整实名认证资料并提交新的不可变字段与材料快照；服务端只在认证领域内部匹配未注销主体。已绑定实名认证可能使用的旧账户手机号提示属于单独受限合同，由后续节点决定。

### Trade-off
不披露响应会增加申请人的重复录入成本，也取消企业信用代码自动填充的便利；换取更小的数据枚举面、独立申请证据和一致的个人企业接口语义。

### Consequences
LOG-048、LOG-052 的企业资料预填不再实现。绑定探测 DTO 不携带 profileId、userId 或主体摘要；后台有权详情和 ruoyi-api 非敏感摘要合同不受影响。认证提交仍需防重复、限流并对字段匹配失败使用模糊错误。

### Verification / Migration
测试覆盖个人与企业命中/未命中/已绑定响应字段一致性、无档案资料泄露、OpenAPI 模型不含主体字段、枚举与限流边界，以及新申请快照不复制旧档案字段。

## ADR-027: 个人重新认证以快照意图和版本围栏完成换绑

**Status:** accepted
**Source:** LOG-063, LOG-064, LOG-065, LOG-066, LOG-067
**Supersedes:** none

### Context
个人档案可能仍被旧账户绑定，但合法本人需要用新账户重新认证。立即解除旧绑定会让待审或恶意申请剥夺现有认证；完全禁止换绑又无法处理旧账户不可用。手机号提示同时必须避免形成账户枚举通道。

### Decision
该能力只适用于个人档案。已登录申请人填写完整身份字段并精确命中其他账户 active 绑定后，只能看到旧 system 手机号掩码，并明确确认重新绑定。系统将 rebindIntent、profileId 与旧 bindingVersion 冻结进不可变提交快照，待审期间保持旧绑定有效。只有 workflow finish 或管理员直接批准时，才重新锁定并校验版本，原子追加旧 unbound 和新 active 绑定事件；不要求申请人控制旧手机号。

### Trade-off
允许重新认证换绑能恢复合法本人对档案的账户关系，但把人工审核变成账户接管防线，并增加手机号掩码、版本竞态和旧账户通知需求。要求旧手机号验证码更强地保护现有账户，却会让已丢失旧号码的本人无法恢复。

### Consequences
普通绑定探测继续只返回 BOUND_OTHER；手机号掩码是完整字段精确命中后的受限例外。企业负责人协议不受影响。驳回、撤销、终止、流程失败或 bindingVersion 变化均不切换；成功换绑必须保留双方绑定事件和申请证据。

### Verification / Migration
测试覆盖普通探测无手机号、完整字段命中掩码、字段错误模糊响应、待审旧绑定有效、通过原子切换、驳回不切换、并发解绑/管理员操作版本冲突、重复流程事件幂等及企业路径拒绝。
