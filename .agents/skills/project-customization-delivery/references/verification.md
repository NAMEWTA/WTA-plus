# 验收与追踪报告

## 完成矩阵

先从实际 App、菜单、路由、模块与用户要求建立功能清单。每项记录前提、账户/Client、操作、预期、证据和状态：`passed`、`failed`、`blocked`、`not-run`，仅用户明确移出范围的项目可记 `out-of-scope`。不要把“无配置、无入口、测试 skipped”解释成通过。

全量完成至少覆盖：

- 自有目录、包名、品牌、作者、Logo 和运行产物一致，没有旧新活动实现并存；第三方身份保持。
- 当前工程实际质量门禁通过，新增变更没有引入未修复失败；源码/资产 provenance 可验证。
- 每个 App 与后端本地运行，连接所选中间件；部署模式的目标服务 healthy、持久化归属和备份可核对。
- 范围内真实浏览器交互与关键权限负向场景通过，发现问题已修复、复测。
- 报告、迁移清单、运行方法、证据和回滚步骤持久化完成。

## 真实浏览器

优先使用会话内可调用的内置浏览器。先核查工具，不能仅因用户提到浏览器就声称可用。若不存在，说明限制并在用户允许的工具范围内使用可用的真实浏览器自动化（如 Playwright）；一般等价测试手段无需重复授权。用户明确限定只能用内置浏览器时，替代方式必须取得同意后执行。

实际填写表单、点击按钮并等待真实请求结果；正常验收不使用 `page.route`/接口 mock、预置登录 Token 或绕开权限注入会话。验证码通过真实图像人工识别或项目原有获授权测试机制处理，不能关闭安全开关伪造真实环境通过。浏览器缺失时先继续 API、构建及脚本准备，将浏览器验收记为阻塞。

依据实际功能覆盖登录/注册/退出/刷新会话、动态菜单、查询与分页、代表性 CRUD、表单校验、角色/Client 隔离、个人与企业业务、上传下载、通知、工作流等；不存在或未在范围内的模块不凭空添加。只遍历菜单不等于整体功能已验收。Admin 与 Home 使用各自 Client 和账户，验证自服务白名单以及管理端拒绝行为。

写操作使用唯一测试数据标识，事先明确清理方式；不删除用户原有业务数据。保存点击清单、截图、页面/网络错误、trace 和必要的脱敏 API 证据。清理本次对象并验证无遗留；操作日志等不可删的正常审计记录在报告注明。

## 外部能力与重跑

仅对范围内实际启用的外部能力补充配置。缺少模型、短信、SMTP、解析器、MQTT 等配置时，明确哪些场景无法运行，询问配置来源或范围取舍；不要自动排除功能、过度部署或代发真实消息。向真实人员发送通知、邮件或短信需要已有明确授权。

API 探针、单元测试、mock E2E 和真实浏览器分别记录，不能互相替代。出现存量 schema 标记缺失、并发测试碰撞或认证参数缺失时先修正测试前提；不得降级认证、去掉断言或把失败记录改成 skipped。

## 持久化交付

默认持久化目录是 `<local_root>/temp/relase/`，用户指定时采用指定目录。必须创建并清楚区分：`deployment-docs/` 存放详细部署文档（服务、具体服务器地址、持久化路径、端口、账号、密码、启动/停止、备份恢复；权限通常为 `0600`）；`tests/` 存放所有截图、测试结果、运行日志、trace 和构建证据（复制前脱敏，权限按证据敏感度限制）。长任务在 `temp/relase/worklog.md` 记录目标、规范化参数、阶段、关键决策、变更与下一步。另可在 `deployment-docs/` 放置不含秘密的摘要报告。

部署文档必须包含：服务器 SSH 地址/端口/账号/密码、远程持久化根、Compose 项目和文件、每个服务的地址/端口/账号/密码、应用本地地址和账号、私密配置位置、启动停止、健康状态、备份和恢复命令；若用户没有提供或没有授权某项凭据，写“未提供/未启用”，不要编造。

测试目录至少保留：部署前后审计、健康检查、服务连接、构建/单元/API/E2E/浏览器证据、截图和失败日志；失败、跳过和未运行必须保留原始状态。

报告包含：

1. 最终状态与范围，所有用户参数的脱敏摘要、源/目标及真实 Git 或归档来源。
2. 名称/路径映射、第三方和历史保留清单、公开合同与状态兼容影响。
3. 实际文件改动、生成产物、初始化/增量数据变化、问题与修复记录。
4. 仅实际部署的服务、镜像、端口、网络、挂载、健康、备份摘要；未部署时写明无部署。
5. 每条质量门禁的命令、工作目录、退出码、passed/failed/skipped 数；真实交互矩阵与证据路径。
6. 测试数据清理、秘密配置位置、本地启动/停止命令和仅限当前项目的恢复步骤。
7. 未验项、残余风险、缺失输入和精确下一步；不能用“整体完成”覆盖未解决的必验项。

`temp/relase/` 及子目录必须加入目标项目忽略规则。部署文档按用户要求可包含明文凭据，但只提供给受控运维人员；测试截图、trace、日志和备份可能包含秘密或业务数据，复制前脱敏并限制权限。最终回复链接部署文档和测试目录，聊天回复不要复制密码。
