## Q2 证据

- objective_id: OBJ-06
- bloom_level: analyze
- socratic_move: evidence
- expected_evidence: L-006「失败路径 `D:fail-auth`（不写会话）」整节与失败路径图；`AuthController.login` 84–89 行 `R.fail` 且不调策略；`PasswordAuthStrategy.validateCaptcha` 先删 Redis 键再抛异常，`LoginHelper.login` 在其后；`SysRegisterService.register` 无 `LoginHelper.login`；`LoginHelper.login` → `StpUtil.login` + token session `loginUser`；`PlusSaTokenDao` 走 `RedisUtils.setCacheObject`
- difficulty: high

**必查项：失败路径存储（不写会话）是否同时写在 Lesson 与源码里。**

结论：**两边都有，且因果顺序对齐。** 不是「课写了源码没有」，也不是「源码有课没写」。

| 闸门 | Lesson 是否写明不写会话 | 源码是否在 `LoginHelper.login` 之前失败 |
| --- | --- | --- |
| 缺 Client / grant 不对 / Client 停用 | 有。前端 `clientEnabled=false` 不发 POST；后端 `AuthController.login` 直接 `R.fail`，「不进入 `IAuthStrategy.login`」 | 有。`clientService.queryByClientId` 空或 `grantType` 不包含 → `return R.fail(auth.grant.type.error)`；`status` 非正常 → `auth.grant.type.blocked`。之后才 `IAuthStrategy.login(...)` |
| 验证码失败 | 有。`validateCaptcha` 抛过期/不匹配，「不调用 `LoginHelper.login`」；键在比对前已删 | 有。`PasswordAuthStrategy.login`：开关开着才 `validateCaptcha`（`get` + `deleteObject`，null → `CaptchaExpireException`，不匹配 → `CaptchaException`）。`LoginHelper.login` 在 `authenticate` 之后 |
| 密码策略拒绝 | 有。精确位置：login 不调 `validateOrThrow`；前端 `register()` 违规不 POST；后端 uniqueness 之后、`BCrypt.hashpw` 之前 `validateOrThrow`，失败不 `registerUser`、更不 `LoginHelper.login` | 有。`AuthController` 注入了 `PasswordPolicyService`，`login` 不用它；`clientContext` 在 Client 启用时才 `publicProjection()`。`SysRegisterService.register` 第 98 行 `validateOrThrow`；全文件无 `LoginHelper.login`。`PasswordPolicyService.validateOrThrow` 抛 `ServiceException("密码不符合安全策略")` |

成功时的唯一会话写入点也两边对齐：`PasswordAuthStrategy` 在验证码与 `authenticate` 之后才 `LoginHelper.login` → `StpUtil.login` + `StpUtil.getTokenSession().set("loginUser", loginUser)` → `PlusSaTokenDao` Redis；前端 `parseAccessToken` 看到 `access_token` 才 `session.setToken`。`AuthController.login` 成功后欢迎通知失败只 warn，不能回滚已写会话——课与源码一致。

## Q3 假设与反例

- objective_id: OBJ-06
- bloom_level: evaluate
- socratic_move: assumptions
- expected_evidence: L-006 正例 4/5、反例 1–4、误区 6/7；`SysRegisterService.register` 成功路径仍无 `LoginHelper.login`；`PasswordAuthStrategy` 字段 `SysUserMapper`；`SysMenuServiceImpl.selectMenuTreeByUserId` 的默认角色 `mergeMenus`；`SysLoginInfoServiceImpl.recordLoginInfo`
- difficulty: high

课的隐含假设：合格读者能把「柜子空」说成会话柜，不会把走廊上其它写入当成登录成功；抄近路只发生在领域 GET 段。工作树反例：

1. **注册成功也不写会话。** 课只把「不写会话」绑在失败 C。`SysRegisterService.register` 成功只 `registerUser` + `grantUserType` + 记 REGISTER 日志，从不 `LoginHelper.login`。读者可能把「注册成功」口述成已经拿到 `access_token`。
2. **失败时并非所有柜子都空。** 闸门 2 删验证码键（课有写）并 `recordLoginInfo(LOGIN_FAIL)` → 异步插入登录日志（课未点名表）。闸门 1 的 `GET /auth/client/context` 仍读 Client 表，返回 `R.ok` 且 `clientEnabled=false`，不是 500。若读者把「不写会话」说成「失败路径零存储」，与源码不符。
3. **登录走廊自己持 Mapper。** 课的抄近路教材是 `DemoPage` 直写 axios、`TestBatchController` 注释「直接引入mapper」。`PasswordAuthStrategy` 却 `private final SysUserMapper userMapper`，`loadUserByUsername` 用 `userMapper.lambda()`，不经 `ISysUserService`。这是主路径上的层跳跃，不是 demo 反例。
4. **`getRouters` 不是「用户角色 join 完就结束」。** 课：超级管理员 `selectMenuTreeAll`，否则 `selectMenuTreeByUserId`（QueryBuilder join 菜单/角色菜单/用户角色/角色）。源码还 `mergeMenus(..., selectMenuTreeByRoleId(defaultRoleResolverService.resolveRoleId(clientId), clientId))`。缺默认角色这条边时，读者会把「白页但已登录」只归因于 token / `clientPk`。
5. **密码输错不在本格，但仍不写会话。** 课边界已声明 BCrypt 不匹配不在 `D:fail-auth`。合格读者仍可能把矩阵三闸背成「登录失败的全集」。

问：读完后，读者会不会把注册成功当成已登录？会不会把验证码失败后的登录日志当成「已经写了会话」？会不会对 `PasswordAuthStrategy` 持 Mapper 说「入口可以直连仓库，因为 demo 也这样」？

## Q4 视角

- objective_id: OBJ-06
- bloom_level: evaluate
- socratic_move: viewpoints
- expected_evidence: 矩阵 (d) `Mapper XML → MySQL`；`TestDemoServiceImpl.queryPageList` vs `customPageList`；`SysMenuMapper.xml` 空壳在 `resources/mapper/system/` 而非 Java 同目录；`createAxiosBrowserAdapter` 默认头 `clientid`；`SysMenuServiceImpl` 默认角色合并；矩阵该失败格备注 `L-006, L-012`
- difficulty: high

从数据流边（源 → 变换 → 汇 + 存储点 + 所有权）看，课图还缺或画滑的边：

1. **主走廊 GET 不执行 XML `<select>`。** `/demo/demo/list` → wrapper `selectVoPage`（Mapper 接口上有 `@DataPermission`）；`TestDemoMapper.xml` 只有 `customPageList` 给 `/page`。菜单树 SQL 在 `SysMenuMapper.java` 的 QueryBuilder；`SysMenuMapper.xml` 确是空 `<mapper>`，但磁盘在 `src/main/resources/mapper/system/`，不是 Java「同目录」。layered 对照 `GET /notify/notice/list` 同样走 DAO wrapper，XML 可见的是 `selectByIdForUpdate`。若 (d) 轴要求「Mapper XML → MySQL」为实线，主走廊目前是虚线合同面。
2. **Client 标识怎么进门厅。** 课写 `clientId` 查询参数或请求头 `clientid`。前端 `prepareLogin` 的 `GET /auth/client/context` **不带 query**；`admin-web` `http.ts` 把 `VITE_APP_CLIENT_ID` 交给 `createAxiosBrowserAdapter({ client })`，适配器默认头 `clientid`。缺这条边，读者会以为 domain 自己把 `clientId` 写进 URL。
3. **`getRouters` 的默认角色汇。** 见 Q3。菜单存储点仍是 MySQL `sys_menu` 等表，但变换多一刀默认角色。
4. **格子所有权。** 矩阵 `D:fail-auth` 备注 `L-006, L-012`。课把验证码限流内部、`PasswordPolicyService` 细节推给 L-012，自己只收「不写会话」判决。从覆盖尺看：L-006 是否已经能把该格标到「存储点 + 所有权」，还是必须等 L-012 把限流键与策略字段讲完？

问：`D:happy-login-query` 若主走廊不碰到 XML `<select>`，Lead 能否仍凭「XML 是合同面」标 covered？`D:fail-auth` 的会话空柜是否已够，L-012 只拥有策略/验证码内部副作用？
