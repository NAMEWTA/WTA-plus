课的隐含假设若反转，合格读者会把哪扇窗的柜子认错？

1. **「矩阵 (a) 没写 add/edit = 没有这两枪。」** 三扇都有 `POST /` 与 `PUT /`。读者按 claimed_cells 口试会漏同父同名、换父改 ancestors、编码只读。反例是课自己的 Goal 合同句。
2. **「三扇门 optionselect 空参=全量。」** 只对部门（再加正常+数据权限）成立。岗位空参是 `[]`。登录域下拉不叫 optionselect。
3. **「`GET /system/post/deptTree` 在部门控制器 / 权限是 `system:dept:list`。」** Java 名在 `SysPostController`，权限串是岗位 list。用户树、角色树另两扇（L-015 / L-016）。
4. **「list 看不见的行，export 一定看不见。」** 岗位分页走带 `@DataPermission` 的 `selectPagePostList`；export 走无注解 `selectVoList`。
5. **「getInfo 都先 `checkDeptDataScope`。」** 只有部门详情。岗位/登录域缺行 `R.ok(null)`，无数据范围闸。
6. **「`SysUserType` = HR 员工类型字典。」** 矩阵备注仍喂这口。类注释、表注释、Excel、会话字段都是登录域。
7. **「停用登录域的两条 HTTP 同一套踢人闸。」** 已停用再 PUT `/changeStatus` 仍 kickout；同样状态再 PUT `/`（edit）不 kickout。读者按「两条都能走到」会把 edit 的幂等停用也说成撕 Redis。
8. **「add 的 `@Validated(AddGroup.class)` 会跑字段上所有注解。」** `@Pattern` / `@Size` 在 Default。非法编码可以进 `insertByBo`，直到唯一键或列宽。
9. **「前端工厂没有的枪后端就没有。」** `changeStatus` / `listByUser` / 两处 export 仍在 Controller。`userTypes` 类型还留着可选 `changeStatus?`，实现没冻进去。
10. **「删除失败都是 `R.fail` / 都是 601。」** 部门业务拒绝 601，行还在；岗位/登录域 `ServiceException`。`toAjax(0)` 才是普通 fail。
11. **「`@CacheEvict` 只在踢人成功后发生。」** changeStatus `rows==0` 仍全表 evict。把 (b)「失败不写」扩成「失败零缓存」会被打脸。
12. **「这三间有 UseCase，因为 system 很大 / 新模块也可以再抄 ServiceImpl 抱 Mapper。」** 登记表 classic；新房间默认 layered（L-003）。

问：读完后仍说不出的，是不是「三扇门的名字」，而是 **哪些窗算本格、(b) 踢人两条闸是否同一、编码注解到底在哪一组、optionselect 空参三套答案**？
