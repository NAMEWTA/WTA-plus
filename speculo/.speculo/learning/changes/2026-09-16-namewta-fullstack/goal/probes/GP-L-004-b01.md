## Q3 假设与反例

- objective_id: OBJ-04
- bloom_level: evaluate
- socratic_move: assumptions
- expected_evidence: L-004「`src/views/` 剩下的是终端私有壳：登录/注册、401/404、SSO 回调、账号资料页」；实际 `admin-web/src/views/`；`adminManifestRegistry.ts` 把 `@/components/FileUpload` 注入 workflow runtime；`FileUpload/index.vue` 对 `@namewta/web-kit-file-upload` 的包装；home 的 `createProfileSelfWebDomain` vs admin 的 `createProfileWebDomain`
- difficulty: high

课的隐含假设：厅堂 `views/` 只剩私有壳，可复用 CRUD 已下沉；「子集」= 少点几个包。工作树反例：

1. `admin-web/src/views/` 除课点名的壳之外，还有 `index.vue`（常量路由工作台）、`redirect/index.vue`、`monitor/external/index.vue`（iframe 运维入口，挂在 `admin-external-monitor` manifest 上）。「剩下的是私有壳」清单不闭合。
2. `src/components/FileUpload/index.vue` 不是领域页，但是 web-kit 的终端包装器，再被 `adminManifestRegistry.ts` 作为 `fileUpload` 注入 web-domain runtime。课把「App→web-kit」画成旁路箭头，没有说清这是**注入**不是 web-domain 反向 import App。
3. home 与 admin 都 `createProfileService`，但 web-domain 工厂不同：home 是 `createProfileSelfWebDomain`（manifest id `web-domain-profile-self`），admin 是 `createProfileWebDomain`（档案管理）。子集不是同一份菜单少点两道菜。
4. home 依赖 `@namewta/domain-system` 却不依赖 `web-domain-system`，因为 `createIdentityAccessService({ identity: systemService.identity, ... })`。课表里写了 domain-system，没解释「有 domain 无 web-domain」不是漏接。

问：合格读者读完后，仍会不会把 `views/monitor/external` 或 `components/FileUpload` 当成「还没搬完的 CRUD」？仍会不会把 home 的 profile 说成「admin 档案页的瘦客户端」？

## Q4 视角

- objective_id: OBJ-04
- bloom_level: evaluate
- socratic_move: viewpoints
- expected_evidence: L-004 口诀「App → web-domain → domain → platform」+ 旁路「App → adapter / web-kit」；`frontend/tooling/architecture/src/index.mjs` `runtimeLayerAllowlist.app = {adapter, domain, platform, web-domain, web-kit}`；`admin-web`/`home-web` `package.json` 直接依赖 `platform-app-runtime` / `platform-auth` / `platform-permission`（admin 另有 `platform-contracts`、`platform-validation`）；`adapter-axios-browser` 依赖 `platform-http`，两厅堂都不直接依赖 `platform-http`；`frontend/README.md` 与 `01-module-map.md` 仍把公开入口写成 admin-web
- difficulty: high

从门禁实现者的视角，课的方向图缺边：

1. **App → platform 是一等边**，不是必须经过 domain。`composeAppRuntime`、`requestRelogin`、`createSsoAuth` 都是 App 直连 platform。口诀只把 platform 画在 domain 下面，旁路只承认 adapter/web-kit。
2. **adapter → platform-http**：HTTP 插头形状在 `packages/platform/http`，浏览器实现在 `adapter-axios-browser`；App 拿 adapter，不拿 `platform-http`。课图把 adapters 画在 platform 之下，但没说清谁 import 谁。
3. **注入 ≠ 反向依赖**：web-domain 收 FileUpload/Editor 是 App 传入 runtime 对象；`runtimeLayerAllowlist` 仍禁止 web-domain → app。
4. **C-001 文档集不完整**：课并列了根 README（三终端已激活）、`docs/namewta-enhancements.md`（发布面 admin+home）、`00-project-profile.md`（唯一可构建 admin-web）、`frontend/apps/README.md`（只点 admin/home）。未列入 `frontend/README.md`（「当前激活 admin-web 和 home-web」）和 `01-module-map.md`（`plus-ui` 公开入口仍写 `apps/admin-web/src/main.ts`）。冲突还在，来源少了两份。

问：`C:frontend-direction` 若只教口号箭头，Lead 能否把该格子标 covered？还是必须与 `runtimeLayerAllowlist` 对齐后再标？
