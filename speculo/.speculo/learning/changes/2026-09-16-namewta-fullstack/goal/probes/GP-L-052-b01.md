1. **「Outbox 有管理端 Controller / 菜单。」** 本切片无 HTTP。课误区 1。厨房也没有 outbox 页（L-053/L-054）。
2. **「wake 的 outboxId 就是任务主键，Worker 按 ID `dao.outbox` 直投。」** `onWake` 把 signal 丢掉，始终 `claim(owner)`。课反例 1；单测 `wakeDoesNotDirectDispatchFutureNextAttemptHint`。
3. **「本地 `@EventListener` 就够了，Redis 是优化。」** 注释与 Publisher javadoc：Redis 是多实例主路径，本地是辅信号。单实例「看起来能工作」，另一进程不会被叫醒。课误区 3。
4. **「claim 返回后仍持行锁直到短信结束。」** UseCase 事务在 `claim` 方法结束时提交；之后才 `dispatch`。锁换成 lease 字段。课误区 4 / 反例 2。
5. **「把 claim 和 `notifyClient.send` 放进同一个 `@DSTransactional`。」** 与「事务结束后才能执行供应商 I/O」相反。ClaimService javadoc 24 行。
6. **「领取失败会把行标 DEAD_LETTER / DONE。」** `claimOutbox != 1` 只是 filter；本 Worker 不 `finish`。DEAD_LETTER 是 dispatch 打满 `maxAttempts`。课 (d) 操作定义。
7. **「`selectClaimable` 只领 READY。」** PROCESSING 且 `lease_until<=now` 会被选中——超时回收。课边界 / 暂停题。
8. **「`WAITING_RECEIPT` / `DEAD_LETTER` 也会被 claim 扫到。」** where 名单只有 READY/PROCESSING。retry 的 `requeue` 先打回 READY（L-051）。
9. **「Redis 订阅失败进程不得启动。」** Subscriber catch 后 warn，poll 仍在。课正例 2。
10. **「Redis publish 失败会回滚已提交的 Outbox。」** AFTER_COMMIT 里 catch，只 warn。行已是 READY，等 poll。PublisherTest `redisPublishFailureDoesNotEscapeAfterCommit`。这是 (d) 的「唤醒失败仍待领取」。
11. **「wake 比事务提交更早发出，别的进程能领到未提交行。」** `@DsTxEventListener(AFTER_COMMIT)` 防的就是这竞态。课暂停题；PublisherTest 提交前 transport 仍空。
12. **「Publisher 是 ClaimUseCase 的字段。」** UseCase 只注入 ClaimService。课反例 3。写路径在 Runtime→event→Publisher；读路径 Subscriber/Worker。
13. **「续租失败还能 `dao.update(delivery)` / `finishOutbox`。」** 第二次 `renewLease` 在 I/O **之后**、写库 **之前**；失败直接 return。课误区 5 / notification.md 35。
14. **「本课覆盖 `NotificationController.submit`，所以 (d) 通知提交可 covered。」** 写篮是 L-051。本课只保证篮子里已有 READY 之后如何领。把假设反转后，Lead 会用本行假闭合四枪 HTTP。
15. **「`dispatch` 供应商 I/O / 限额 / backoff 是本格 (b)。」** 课图边界写明不展开。矩阵 (b) `NotifyClient.send` 是 L-082。
16. **「回调也要先 claim。」** 课迁移段：回执改 Delivery 并 `refreshAggregate`（L-050）。
17. **「同 JVM 只会 drain 一次。」** Publisher 先 Redis 再本地事件；同机可能进两次 `drain`。互斥靠 skip locked + token，不是 Worker 锁。课没写成误区，磁盘如此。
18. **「空篮子上的 wake 会报错。」** 空列表，do-while 立刻停。课变式 A。
19. **「矩阵要先有 skip locked / AFTER_COMMIT 独行才算 (b) 讲完。」** 矩阵无这些行。它们是 (b) 的 explained。
20. **「(a) 无 HTTP 必须等改 chain 才盖章。」** 课开篇第一句就是。同名类已在矩阵 (a)。
