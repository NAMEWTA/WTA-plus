课的隐含假设若反转，合格读者会把哪只手环或哪张座位票认错？

1. **「`SsoSessionUseCase.session`。」** 没有这个方法。HTTP 才叫 `session`，用例是 `current`。课误区 2 覆盖。
2. **「`Sso-Token` Cookie 就是 Sa-Token / `IssuedToken.accessToken`。」** 一个是 Redis 会话标识，一个是换票产物。课误区 1 / 第二张图覆盖。
3. **「登录 JSON 里能抄到 sessionId 或 access_token。」** `R.ok()` 空 data。要座位票走 L-056 `exchange`。课反例 3 / 变式 D 覆盖。
4. **「登录会 `SsoTokenExtras.bind` / `buildLoginUser` / `LoginHelper.login`。」** 会话 Service 只 `verifyPassword`+`create`。单测假端口在 `buildLoginUser` 抛错，成功 login 仍能通过。开柜在换票（L-056），不是本窗。L-013 变式 F 把「开柜」写成 L-055/L-057，口试不要跟着把本窗说成发业务票。
5. **「logout 是跨 App SLO，会 `SsoBusinessTokenPort.revoke`。」** 只 `sessionPort.delete` + 空 Cookie。已发出的业务票按自己的超时活。课正例 3 / 误区 4 / 变式 B 覆盖。
6. **「`SsoOAuthController` 用 `SsoSessionCookie` 读环。」** 两边都是手写 `readSessionId`。`SsoSessionCookie` 只有 `create`，且全仓只被 Session 控制器调用。课误区 5 覆盖。
7. **「未登录和 authorize 的 `loginRequired` 同一套返回。」** 前者 `R.fail("未登录")`（JSON code 500），后者 `R.ok` + 布尔。前端不能用同一判断。课误区 6 覆盖。
8. **「空白密码 HTTP 也回『用户名或密码错误』。」** 控制器 `@Valid` 先挡。Service 那句只保护直呼 UseCase/Service。真错密是身份端口文案（L-059）。课把两层说成统一句，过满。
9. **「前端 `document.cookie` 写一个假 Sso-Token 就能进。」** Redis 无挂牌则 `find` 为 null。HttpOnly 挡的是脚本读真值，挡不住任意客户端带 Cookie 头。课反例 2 覆盖。
