## 1. 实现摘要

HTTP/TLS 两份 LB 模板新增相同的 `nacos_server` upstream，将 `/nacos/` 原样代理到 `nacos:8848/nacos/`，保留标准 forward/upgrade headers、长读超时和无缓冲。代理不注入 Authorization/Cookie，不删除 Nacos CSP/frame header，也不加入 wildcard CORS。真实故障注入发现默认连接等待过长后，为该 location 增加精确 `proxy_connect_timeout 5s`，使现有维护页及时生效。

前端新增 Playwright 合同：验证有 `system:nacos:console` 权限才创建 `/nacos/` iframe，iframe 请求不携带 RuoYi token/cookie；无权限时不创建 frame/request。设置 `NACOS_LIVE_BASE_URL` 后，还会在真实代理 origin 中加载官方登录、二次嵌入同源 iframe、验证静态资源和匿名 403，并输出截图。

## 8. 偏差与决策

- 真实故障测试发现默认连接等待无法及时展示维护页，属于 T-05 location 内故障语义，已增加 5 秒连接超时并补静态/真实回归。
- 官方 Nacos 登录页初始化会匿名请求配置列表；每个 frame 产生一个预期 API 403，并由 Chromium 记录通用 `Failed to load resource: 403`。测试严格要求这些 console 条目与已识别 API 403 一一对应，其他静态资源/console 错误仍失败。
- 远程 tar 在 `umask 077` 的隔离目录创建了不可遍历父目录，第一次维护页读取失败；把测试目录恢复为源树的 `0755` 后复验通过，不是发布文件或 Compose 权限缺陷。
