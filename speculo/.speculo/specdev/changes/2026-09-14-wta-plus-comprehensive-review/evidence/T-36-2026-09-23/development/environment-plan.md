# T-36 owned MySQL/Redis integration environment (prepared, not executed here)

The only runner is `/tmp/wta-t36/run-notify-atomic-integration.py`. It is opt-in and requires `--execute --expected-head <40-character SHA>`. The Lead owns all Docker, Maven and E2E execution. This preparation changed only `/tmp`; it did not launch a container or touch a shared database.

For a development red proof, add `--development-red` while the expected commit is checked out but the new regression test is dirty. This selects only `NotifyAtomicResultIntegrationTest#attemptInsertFailureRollsBackDeliveryAndLeavesClaimRecoverable`. A valid red requires a fresh exact-class Surefire XML with exactly that method, one assertion failure, no errors or skips, and nonzero Maven exit. The runner can return 0 for that observed red only after owned cleanup, but its JSON always says `mode=development-red` and `acceptance=false`. It records HEAD/tree, dirty-status hash, tracked diff hash and target test file hash before and after. A compile error, fixture error or unrelated test failure is not a red proof.

For final acceptance, omit `--development-red`; the runner demands the exact clean HEAD both before and after, and selects **both** `NotifyAtomicResultIntegrationTest` and `NotifyWakeIntegrationTest`. It enables `notify.atomic.integration=true` and `notify.wake.integration=true`, with `-DforkCount=1 -DreuseForks=false`. It requires a fresh exact Surefire XML for each class, positive tests and zero errors/failures/skips. The class/method counts and Maven exit are recorded. The currently hard-coded credentials in `NotifyCallbackProcessProbe` must be reconciled by the product writer before the full Atomic class can use the random owned application user. The probe must inherit the secret through process environment, never a child JVM argument.

Each run creates two new containers only, using MySQL `8.4.9` and Redis `8.6.3`, with full IDs and exact dual labels `namewta.test.owner=T-36` and `namewta.test.run=<64-bit random run ID>`. Docker publishes only random `127.0.0.1` ports. The owned MySQL starts with `--log-bin-trust-function-creators=1` so the public seed's trigger can be created without assigning global `SUPER` to the app user; the first development attempt stopped at MySQL error 1419 before reaching the business assertion. Six public SQL seeds initialize a newly named `namewta_notify_test_<run ID>` database; the runner asserts 103 application tables and grants a random application user only on that new database. It does not use a shared service, call a supplier or write production configuration. Redis is an unauthenticated, loopback-only, nonpersistent new instance.

Synthetic passwords exist only in memory, Docker `--env-file` (0600), SQL stdin and the Maven child environment `T36_MYSQL_PASSWORD`. Maven argv carries only the nonsecret JDBC loopback URL, user name and Redis port. Raw Maven output is held in 0600 storage, sanitized, then deleted. The runner never prints Docker inspect environment or secret-bearing commands. It creates no external application state.

Maven runs in its own process group. The runner checks and terminates any surviving JVM even when the Maven leader has exited, then finds containers by both labels with `docker ps -aq --no-trunc`, verifies each label, removes exact owned full IDs, confirms no owned containers remain and confirms all published loopback ports are closed. Cleanup failure makes the runner exit nonzero even if the selected test passed or the expected red was observed. The JSON result and sanitized log remain in a 0700 run directory; environment files are removed. These records are preparation/runner output, not a Ticket or current-candidate Evidence until the Lead fixes the source commit and executes it.

Safety-only checks are saved in `/tmp/wta-t36/verification`; they do not start Docker or Maven. The final runner hash and current synthetic count are reported separately after the trigger-option update.
