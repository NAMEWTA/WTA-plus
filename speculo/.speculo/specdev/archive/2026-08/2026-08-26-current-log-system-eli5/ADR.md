# 系统运行日志优化架构决策

## ADR-001 — 系统日志按 Filter 边界原样记录认证凭证

- **状态：** accepted
- **日期：** 2026-08-26
- **来源：** LOG-011, LOG-013
- **上下文：** 现有 `CryptoFilter` 在应用链路之前解密请求，并在应用链路完成后加密响应。位于其下游的系统日志 Filter 因而可以看到解密后的请求正文和响应加密前的正文。项目安全规范 `SEC-003`/`SEC-005` 默认禁止把密码、token、验证码、secret 等写入持久日志，但用户在了解重放窗口与 60 天副本风险后，仍要求排障日志完整保留 Filter 捕获到的原值。
- **决定：** 当前 change 的系统 HTTP 日志以日志 Filter 所见内容为边界；在 1 MiB 单方向上限内，普通 JSON/文本正文中的密码、验证码、access/refresh token、client secret 及其他认证凭证不脱敏、不排除，原样进入 `sys-console.log`。这是仅适用于当前 change 和该系统日志链路的 `SEC-003`/`SEC-005` 明确例外。
- **方案权衡：** 排除或遮盖凭证能显著降低日志成为第二份凭证库的风险，但会偏离用户要求的完整原值排障合同；原值记录提高问题还原能力，同时意味着日志访问者在凭证有效期内可能直接重放凭证。
- **后果：** 系统日志的访问、备份与 60 天留存会同时承载认证数据；实现者不得默默恢复脱敏，也不得把此例外扩展到 `@Log`、数据库审计或其他 change。文件、multipart、流式正文排除和 1 MiB 上限仍然生效。
- **验证：** 测试应证明日志记录的是 `CryptoFilter` 解密后的请求和加密前响应，且凭证字段值未被改写；同时证明超限截断及非文本正文排除仍然有效。
- **替代/被替代：** 无
