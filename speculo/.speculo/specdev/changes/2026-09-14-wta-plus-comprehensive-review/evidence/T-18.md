## 输入与实现

- `T-18-input-checkpoint.json` 核对上游最新 236 路径；`T-18-checkpoint.json` 保存本票 24 个产品/测试路径。231 个上游非重叠路径 hash 未变，5 个共享路径按最新 owner 接管。预期写集中的 `types.ts` 最终无需修改。
- OSS adapter 只在 complete 返回有效 ID 后报告上传成功。下载地址失败返回空预览，删除原无 owner 的 Blob URL fallback；保留文件 ID、名称和已完成对象。私有对象列表本来不提供地址，resolve 通过现有 downloadUrl 单独解析，单个失败不丢失引用，也不重新上传。
- 两个 Web Kit 上传组件显示文件名、预览不可用及重试；异步解析按组件 generation 忽略过期结果。上传 request 持有局部 AbortController，取消/卸载即时结束 pending，成功、失败、同步异常、迟到进度或响应只结算一次。新 busy 事件供实际 OSS 对话框使用，上传未完成不能确认，关闭销毁组件。Element Plus 创建的图片 Blob URL 在成功替换、错误、移除、卸载时释放；不新增通用 dispose 或 detach/delete 双接口。
- 用户导入移除创建页面时缓存的请求头与直接 action，改用现有 System runtime 的最小 importUsers 方法和 App HTTP。每次请求读取当前令牌/Client；FormData 保留浏览器 multipart boundary，updateSupport 传布尔查询参数。局部 useUserImport 负责错误、busy、取消与旧响应隔离，关闭后可以重开并重试。
- Workflow 导入按实际 Element Plus 合同调用成功/失败回调，并使用同一 HTTP signal 能力；关闭对话框中断传输、结束 busy，旧响应无权修改新对话框。业务错误保留可见消息并允许重新选文件。
- HttpRequest 增加可选 signal；Axios 合成调用者与 T-12 会话取消信号，结算后移除监听器。HTTP 401 与业务 401 复用既有单次恢复，不改变 Client 注入、后端权限、退出取消代次。FormData 不再继承 JSON Content-Type。传给 Element Plus 的异常只含展示消息和安全元数据，避免组件记录底层请求头。
