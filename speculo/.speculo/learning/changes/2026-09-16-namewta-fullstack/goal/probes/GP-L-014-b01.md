## Q3 假设与反例

- objective_id: OBJ-14
- bloom_level: evaluate
- socratic_move: assumptions
- expected_evidence: admin `views/login.vue` / `register.vue`；home `RegisterPage.vue` / `router/index.ts`；`socialLogin`/`socialCallback`；admin Pinia `ROLE_DEFAULT`；`parseAccessToken` 不 trim
- difficulty: high

课的隐含假设若反转，合格读者会把哪一枪或哪只抽屉认错？

1. **「登录页 = `prepareLogin`，注册页 = 拆枪」。** 读者打开 admin `views/login.vue` 会以为厅堂漏接 web-domain；打开 home `RegisterPage.vue` 会以为门户「拆枪没拆完」。真实分流是 **admin 两页都拆枪，home 登录+注册都走 `prepareLogin`**。拆枪能竖旗，是因为 `getVerification` 成功结尾写 `prepared=true`——这一句仍对，但「哪一页」写错了。
2. **「只有 `login` 往抽屉塞钥匙」。** 若 (b) 被读成「工厂里唯一的 `setToken`」。`socialLogin` 必写；`socialCallback` 条件写。密码登录仍是 OBJ-14 主路径；读者可能把社交回跳写成「必须先 `prepareLogin`」——源码是 `ensureClientContext`，不看旗。
3. **「`getInfo` 空 roles 就是空权限」。** domain 把坏数组降成 `[]`。admin Pinia 接着写成 `['ROLE_DEFAULT']`；home 原样拷贝。读者按课口述会漏掉管理端这一层改写。这不是工厂合同，是厅堂消费。
4. **「综合测试已经断言 register 不写 session」。** 没有那条 expect。读者可能把「测试覆盖」说成比源码更强的证据。
5. **「`access_token` 会 trim」。** `parseAccessToken` 只拒绝全空白，返回原字符串。带空格的票会被 `setToken` 原样塞进抽屉。课强调蛇形字段名，没强调不 trim。

问：读完后仍说不出的，是不是六枪 URL，而是 **哪座厅堂的哪一页在竖预备旗、以及矩阵行上的社交写手算不算本格**？
