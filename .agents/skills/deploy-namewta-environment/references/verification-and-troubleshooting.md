# 验证与排障

| 范围 | 必需证据 |
|---|---|
| 容器 | 必需服务运行/健康，镜像/image ID、restart count、环境摘要与挂载正确 |
| 入口 | 前端、API、监控、SnailJob、SnailAI、Nacos 路径状态正确 |
| 后端 | 双实例健康且零异常重启，直连与 LB 的 HTTP/业务码、登录/验证码和一个鉴权业务请求通过 |
| MySQL | 数据库、表数量、迁移状态和 OSS 不变量正确 |
| Redis | 认证 PING 与应用选定数据库正确 |
| MinIO | 就绪、私有探针、匿名拒绝、签名链接成功后过期 |
| Nacos | 命名空间/分组/Data ID 正确，双实例摘要一致 |
| 可观测 | Monitor 注册、日志、仪表盘与告警责任明确 |
| 安全 | 日志/产物无密钥，内部端口未意外公开 |
| 恢复 | 上一版本、验证过的备份和可执行回滚命令齐全 |

旧审计状态可运行 `scripts/verify-deployment-state.mjs`。v2 发布必须运行 `scripts/verify-release-candidate.mjs`，同时比较 profile 与状态中的 Compose 身份、双实例、业务探针、前端构件、稳定窗口、数据保护和恢复资产。

健康等待期间持续读取容器 state、restart count 和脱敏启动日志；重启循环或确定性装配错误立即失败，不等待总 timeout。LB/前端切换使用有上限的连续成功窗口：窗口内瞬时 502/503 可记录，连续成功不足或超时才失败。

每个业务探针显式声明允许的 HTTP 与业务码。缺失凭据可以是业务 404，接口目录可以是业务 200；不得使用全局“非 200/404 即失败”的粗粒度规则。探针地址从实际 bind host 派生，不固定为 loopback。

## 启动错误：默认 OSS 必须为 PRIVATE

查询 `sys_oss_config` 并确认启用的默认行。当前代码中 `PRIVATE=0`、`PUBLIC_READ=2`。备份目标行后，将预期 `minio` 默认配置更新为 `access_policy='0'`，禁用竞争默认项，清理相关缓存并重启。发布初始化脚本已经执行相同不变量校验。

## Nacos 端口冲突或重启失败

发布端口前先检查所有者。当前开发服务器不发布 Nacos 宿主机端口，统一走入口代理。只用 `--no-deps` 重建 Nacos。客户端异常时关闭可选覆盖，并确认应用从本地基线启动。

## 发布失败

不要立即清理现场。保存容器状态、脱敏日志、清单/校验结果、迁移状态和活动指针，执行已登记的回滚方案。必须脱敏 Authorization、密码、令牌、嵌入凭据的连接 URL 和私钥。
