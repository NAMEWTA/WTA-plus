课的隐含假设若反转，合格读者会把哪扇窗的柜子认错？

1. **「矩阵没写 add/edit = 没有这两枪。」** 三扇都有 `POST /` 与 `PUT /`。反例是课自己的 Goal 合同句和 9+8+7 表。
2. **「`refreshCache` 会把表全量载入 Redis。」** 只 `clear`。HTTP 200 不等于已经抄好新墙。
3. **「字典数据也有 refreshCache。」** Controller 没有；扫帚在类型窗。
4. **「`GET /dict/data/type/x` 打 DataService。」** 打 Type 服务的 `@Cacheable(SYS_DICT)`。
5. **「管理 getInfo/list 走缓存，所以改完列表还旧。」** 相反：旧的是热路径。
6. **「缺键返回 null，所以不会污染缓存。」** 配置缓存 `""`；字典数据缓存 `[]`；**类型 VO 还可以缓存 null**。
7. **「刷新失败 = 墙完全没动。」** `cache.clear()` 在协调器回执之前。本节点 Redis 往往已空；他节点 Caffeine 仍可能吐旧值，最多再活 **写入后** 30s。
8. **「`updateByKey` 和 `edit` 同一套校验。」** 无 `@Validated`、无 unique；密码策略键仍 parse。
9. **「内置 Y 完全只读。」** 只禁删除。
10. **「有数据的字典类型会级联删数据。」** 「{}已分配,不能删除」。
11. **「改一条数据的 dictType，两边缓存都会更新。」** 只 CachePut 新类型。
12. **「`sys_config` 和 `sys_client` 一样 30 天过期。」** 配置/字典名没有 `#`。
13. **「这是 layered，刷新应写 UseCase。」** 登记表 classic。
14. **「`optionselect` / `getConfigKey` / `dictType` 要 list 权限。」** 源码无权限注解，仍要登录。
15. **「有 edit 就能点刷新。」** 刷新挂 **remove**；前端按钮同一串。
16. **「配置刷新也有 Lock4j。」** 只有类型那扇。
17. **「Caffeine 有人访问就不会掉。」** `expireAfterWrite`。把课词汇表「写入/访问」抄进口试，会把「忙节点一直旧」说成机制。
18. **「未知异常编号能当缓存验收。」** 文案不提 cache；要用热路径 GET by key / by type，不要用 list。

问：读完后仍说不出的，是不是「三扇窗的名字」，而是 **哪些窗算本格、刷新失败时墙还剩哪一层、空白复印件有几张（`""` / `[]` / 类型 null）、Caffeine 到底写后续命还是访问续命**？
