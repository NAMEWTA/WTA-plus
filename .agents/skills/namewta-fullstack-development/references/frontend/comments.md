# 注释约定

## 原则

- 注释解释约束、原因、兼容性、安全边界或非显然的状态机，不复述代码。
- 面向仓库维护者的注释使用中文；技术标识、接口名、组件键和协议字段保留原文。
- 新增或实质修改的公共 TypeScript 类型、接口、端口、导出函数和组合式函数使用简明中文 JSDoc，说明语义、参数、返回值和失败条件；简单内部函数不要求机械补齐注释。
- Vue 模板只在复杂区块或框架限制处使用中文分区/原因注释。
- 不添加统一版权头、作者头或无责任人的 TODO。

## 架构注释

domain mapper 应说明异常线上值如何失败关闭；web-domain runtime 应说明为何通过宿主端口注入；App composition 对不直观的选择/排除理由可留短注释。包边界、激活状态与验证要求应写在 README，不用大段源码注释重复。

## 生成内容

`apps/*/src/types/components.d.ts`、`auto-imports.d.ts` 和 `packages/api-contracts` 的生成结果可能带工具注释；不要手工统一或翻译这些生成头。修改生成器配置后重新生成。

## 维护要求

改动代码时只同步受影响注释；发现长期说明与当前包路径、公开入口或父级 Skill 不一致时，应更新或删除。历史迁移原因保留在 Speculo 证据中。
