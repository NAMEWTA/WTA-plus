# 统一通知管理平台

**统一通知平台**：公司业务系统通过一个稳定入口提交通知，由平台集中管理应用、渠道账号、逻辑模板、供应商绑定、路由、配额、投递记录和统计。
_Avoid_: 短信工具类、共享 SDK、只有后台 CRUD 的配置页面

**通知控制面**：`ruoyi-notify` 拥有的业务治理层，负责通知应用、渠道账号、模板、路由、配额、统一 API 和统计；它编排通知数据面，但不复制 Provider SDK 发送实现。
_Avoid_: common-notify、渠道 Adapter、第二套 Dispatcher

**通知数据面**：现有 `common-notify` 及 Mail/SMS Adapter 组成的运行时发送层，负责统一请求、校验、幂等、渠道解析、Provider 调用、结果聚合、附件快照和投递事件。
_Avoid_: 通知管理后台、模板中心、应用配额

**通知应用**：在统一通知平台中代表一个调用业务系统的一等身份，拥有状态、允许渠道、允许模板、配额和审计归属；它不等于 OpenAPI credential、OAuth Client、Platform Client 或 Provider Account。
_Avoid_: Client、租户、appKey、providerKey

**渠道账号**：平台管理的一份可发布 Provider 配置，例如某个阿里云或腾讯云短信账号；它包含供应商类型、签名、运行参数和加密凭据，并通过稳定标识参与路由。
_Avoid_: Notify Channel、调用应用、明文 YAML 密钥

**逻辑通知模板**：业务系统使用的稳定场景编码，与具体供应商模板编号解耦；平台通过渠道内容版本和供应商绑定把它解析为实际发送内容。
_Avoid_: 阿里云模板编号、腾讯云模板编号、业务系统内硬编码正文

**供应商模板绑定**：一个逻辑通知模板的渠道版本与某个渠道账号下 Provider 模板编码、签名和参数映射之间的关系。
_Avoid_: 逻辑通知模板、把 Provider 模板编码直接暴露为公共业务合同

**通知路由**：平台根据通知应用、逻辑模板、渠道和目标属性选择渠道账号及备用路径的受控规则；普通业务调用方不直接决定供应商。
_Avoid_: providerKey 由普通调用方指定、Client 自动路由

**统一通知 API**：由现有 NAMEWTA OpenAPI 机器认证边界保护、面向公司业务系统的稳定 HTTP 合同；认证通过后仍需执行通知应用、模板、渠道和配额授权。
_Avoid_: 浏览器登录接口、直接暴露 NotifyRequest、第二套 HMAC 协议

**同步通知发送**：调用线程完成路由和 Provider 尝试，并返回本次 Provider 接受结果的低延迟模式；适用于验证码等必须立即决定后续业务行为的场景。
_Avoid_: 最终送达、可靠异步任务、HTTP 超时后推断未发送

**可靠异步通知**：平台先持久化受理状态，再由 Outbox 或 durable queue 驱动投递、恢复和重试的模式；受理成功只表示任务已可靠进入平台。
_Avoid_: Spring `@Async` 监控事件、受理即送达、内存任务队列

**原始内容权限**：允许受控内部通知应用绕过逻辑模板正文、直接提交内容的独立高权限能力；它仍受渠道、配额、目标频控和敏感审计约束。
_Avoid_: 普通通知发送权限、默认模板能力、绕过平台治理

**运行时配置快照**：渠道账号发布校验通过后形成、供发送线程只读使用的完整版本；新版本原子替换旧版本，发布失败继续使用上一可用版本。
_Avoid_: 发送期间读取半更新数据库行、修改 YAML 后重启、失败后清空可用配置

**路由快照**：一次通知在开始执行时固定的路由规则版本、候选渠道账号和选择依据；后续配置变化不改写该通知的路由解释。
_Avoid_: 每次重试读取最新规则、调用方指定 providerKey、无法追溯的随机选择

**供应商尝试（Provider Attempt）**：平台对一个物理目标使用一个渠道账号进行的一次实际 Provider 调用；首次尝试和故障切换尝试分别记录状态、耗时、错误与供应商消息标识。
_Avoid_: 逻辑通知、最终送达、覆盖上一尝试

**通知配额**：通知应用在服务端时间窗内可受理或发送的数量预算，与通用 OpenAPI 请求限流分开计算。
_Avoid_: Provider 余额、OpenAPI 限流、tenant 配额

**目标频控**：在调用 Provider 前，按物理目标、逻辑模板和场景时间窗限制重复通知的安全策略。
_Avoid_: 业务幂等键、应用月配额、发送后告警

**模板发布版本**：逻辑模板某个渠道内容经过校验和发布后形成的不可变快照，包含参数 schema；发送只引用发布版本，修改产生新版本。
_Avoid_: 可原位编辑的已发布模板、供应商模板编号、当前草稿

**供应商回执**：经渠道回调适配器验证来源和签名、能够关联具体 Provider Attempt 的供应商投递事实。
_Avoid_: 同步 ACCEPTED 响应、未经验证的回调报文、平台推测结果

**最终投递状态**：基于可信回执形成的 `DELIVERED`、`UNDELIVERABLE` 或无法确认的 `UNKNOWN`；同步 Provider 接受仅为 `ACCEPTED`，不是最终送达。
_Avoid_: 将 ACCEPTED 统计为 DELIVERED、无回执时默认成功

**应用幂等作用域**：由通知应用、逻辑渠道和业务幂等键共同确定的重复请求边界；默认有效 24 小时，应用可在 5 分钟至 7 天安全范围内配置。
_Avoid_: Client 幂等作用域、全平台共享业务键、exactly-once

**通知监控数据保留**：新通知平台按敏感等级和用途执行的生命周期策略；完整正文与参数保留 30 天，脱敏投递明细 180 天，供应商回调摘要 90 天，按日脱敏聚合保留 24 个月。
_Avoid_: 永久保存完整目标和正文、用聚合报表恢复个人内容、沿用旧日志作为兼容权威

**新通知监控合同**：由 ruoyi-notify 直接拥有的任务、逻辑通知、Provider Attempt、回执和统计管理边界；它不保留旧 `/monitor/notify`、`system:notify:*` 或历史数据兼容。
_Avoid_: system/notify 兼容层、新旧日志双写、历史数据迁移

**可靠受理**：异步 API 只有在任务状态已经持久化、能够在进程重启后恢复时才返回成功；它保证平台不会丢失已受理任务，但执行语义是 at-least-once。
_Avoid_: 内存排队后返回成功、受理即 Provider ACCEPTED、Provider exactly-once
