- difficulty: high

课的隐含假设若反转，合格读者会把哪间房间认错？

1. **「占位目录 = 同一条架构门禁」。** 给 `taro-request` 加 `package.json` 会 `placeholder-activation`。给 `ui-element` 加清单则成为合法 web-kit 包。读者按课行事，会以为架构会拦住提前开的 Element 库——它不会。真正门槛只在 README / `FE-CRUD-006`（两个真实消费者）。
2. **「富文本壳已经是多页共用店徽」。** 活消费者只有 `web-domain-demo`。管理厅堂另有 `components/Editor/index.vue`：直接依赖 `@wangeditor-next/*` + `ossUploadClient.upload`，**不** import `@namewta/web-kit-rich-text`。提取口诀「两个消费者才搬进 web-kit」与现状相反：店徽服务 demo，厅堂私货平行存在。
3. **「失败关闭 = 拆节点并抛错」。** 无权限的合法绑定是静默摘 DOM。读者可能把「指令抛错」当成权限拒绝的信号，或把 home 的函数 `hasPermission` 误当成同一条失败关闭。
4. **「App 按课列的六项就能 `createAxiosBrowserAdapter`」。** 缺 `repeatSubmissions` 等必选字段过不了类型。读者可能把重复提交柜写成 adapter 内置，或以为 home 也有 500ms 防重（home 空实现）。
5. **「默认 resume IndexedDB 不算本格存储点」。** `createOssUploadClient` 默认 `resumeStore = createIndexedDbResumeStore()`。课把 IndexedDB 整段推给 L-029。若 `A:adapters` 要讲存储点所有权，浏览器里已经有一只抽屉不是 `Admin-Token`。

问：读完后仍说不出的，是不是「三间房间的名字」，而是 **ui-element 到底谁来拦、厅堂 Editor 算不算第二套壳、axios 插头还有哪些公开出口**？
