## Fixed source and minimum fact contract

`OssClient.diagnoseAccess(String, AccessPolicy, Duration)` (`wta-common-oss/.../client/OssClient.java:400`) already returns public `OssAccessDiagnostic`. The only production implementation is `AbstractOssClientImpl.diagnoseAccess` (`:1003–1080`); the production consumer is `OssStorageReadinessService.diagnose` (`wta-system/.../oss/readiness/OssStorageReadinessService.java:97–141`). The current public record has `Verification`, `Reason`, expected policy, two success booleans, `anonymousWriteDenied` boolean, and one `checkedAt`. `OssStorageReadinessService` collapses the result into `SERVING/NOT_SERVING` and `READY/PROVIDER_MISMATCH/DIAGNOSTIC_UNVERIFIED`. Its single-ID API currently loses partial facts before returning the three-field VO. `OssStorageReadinessEntry`/health are optional summary paths; they must not turn UNKNOWN into evidenced MISMATCH.

The smallest useful replacement is explicit `ALLOWED / DENIED / UNKNOWN` per observation with fixed source, scope, and observation time: Policy read, ACL read, anonymous HEAD, anonymous Range GET for the **named diagnostic object**, and a separately scoped recognizable anonymous-write policy hazard. Policy/ACL 403 means unreadable/UNKNOWN, not an empty policy or a proven deny. `NoSuchBucketPolicy` 404 is a known absence of that policy document, not proof that anonymous read/write is denied. Anonymous object HEAD/GET 2xx (including expected Range 206) is ALLOWED for that object at that time; 401/403 is observed DENIED for that object; 404, timeout, 5xx, unsupported provider or ambiguous redirect is UNKNOWN. No single-object result may claim whole-bucket access or write safety. Preserve independent partial observations when one source fails.

Current `AbstractOssClientImpl` (`:1025–1049`) maps Policy/ACL 403 to empty policy/grants. `PublicAccess.from` (`:1169+`) sees only wildcard Principal/Action Allow and ignores Resource, Condition, Deny and Not*; `:1065–1080` can then assert `POLICY_MISMATCH` or `anonymousWriteDenied=true` without adequate evidence. The new parser should recognize only an explicit, understood unconditional subset, account for Deny and exact resource/action scope, and return UNKNOWN for other policy conclusions. A scoped dangerous write Allow is a warning, not proof that an anonymous PUT succeeded. Do not do anonymous PUT/DELETE or raise application privileges to obtain a definitive answer. Actual owner/Client permission, object ACTIVE/service, current configuration and declared access type still fail closed in ordinary business routes; T-44 already removed diagnostic freshness as their gate. T-45 must not reintroduce it.
