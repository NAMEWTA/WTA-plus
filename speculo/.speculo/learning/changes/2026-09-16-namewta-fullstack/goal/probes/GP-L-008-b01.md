## Q3 假设与反例

- objective_id: OBJ-08
- bloom_level: evaluate
- socratic_move: assumptions
- expected_evidence: L-008 正例 1–5、反例 1–7、误区 1/2/6/7/11/12；`createProfileService` 仍含 `person.archive` / `rebind` / `enterprise.transfer` / `materialTags`；`createIdentityAccessService` 仍含 `social*` 与 `grantType:'password'`；`AuthorizePage` 默认用户名 `WTA`；`loginWithPassword` 不引用 `ssoLoginMethods`
- difficulty: high

课的隐含假设：合格读者能把「只接身份+资料」说成 **产品工厂选择**，不会把对象上多出来的方法当成第三道业务菜；能把认人厅五函数当成完整组合面。工作树反例：

1. **资料插头不是 self-only 服务。** `profileService = createProfileService(domainHttp)` 与 admin 同构：对象上仍有 archive / rebind / transfer / materialTags。产品差在 registry 只挂 self 三键，不在 `services.ts` 裁方法。读者可能口述成「home 的 profileService 没有管理端 API」。
2. **身份工厂带着社交方法。** `createIdentityAccessService` 仍有 `/auth/social/callback`、`grantType:'social'`。home-web 源码搜不到 `social` 调用，但 LoginPage 把第一方 SSO 画在「第三方登录」行里。读者可能把 `startSsoLogin` 说成社交登录，或把「home 不打 `/sso/login`」说成「登录页没有 SSO」。
3. **「只接受 password」不是 `loginWithPassword` 体内的分支。** 约束在模块常量 + 测试。函数对任意字符串 POST。读者可能以为运行时会拒绝 github grant。
4. **空 `VITE_SSO_API` 不是开发漏配。** 课已纠正「空前缀=合同」。但只绑开发代理。生产同样空串，合同是「SSO Origin 同源 `/sso` 由网关反代」。读者可能说「生产应填绝对后端 URL」。
5. **认人厅没有 logout 导出。** 后端 `SsoSessionController.logout` 存在；`sso-web` 全树无 `logout`。五函数表被读成「认人 HTTP 全集」时，缺负例。
6. **注册成功 / SSO 会话成功都不是用户中心已登录。** 课有误区 6。`fetchSession()===true` 只证明 Cookie。`RegisterPage` 走 `identityAccessService.register`，L-014 才钉「成功不 `setToken`」。本课读者仍可能把认人成功与 `Home-Token` 写成一步。

问：读完后，读者会不会把 `createProfileService` 说成「裁过的自助服务」？会不会把 LoginPage 的 SSO 按钮当成社交？会不会把 `ssoLoginMethods` 说成 `loginWithPassword` 的运行时闸？会不会把生产空 `VITE_SSO_API` 当成缺口？

## Q4 视角

- objective_id: OBJ-08
- bloom_level: evaluate
- socratic_move: viewpoints
- expected_evidence: Skill `frontend/architecture.md`「三个入口的集合必须一致」；课变式 D 以工作树裁决 system 配料；`composeAppRuntime.resolve` 忽略 `domainId`；home `application/sso.ts` 与 `requestRelogin` 是 App→platform 一等边；矩阵 (d) `主路径 SSO 授权码` 仍 uncovered（L-055/L-056）；L-009 `A:platform-auth` / `A:platform-app-runtime`
- difficulty: high

从架构边与数据流边看，课图还缺或画在格子外面的边：

1. **Skill 三点门 vs 工作树合法不一致。** 架构文写「三个入口的集合必须一致」。home 的 `domain-system` 在依赖和 `createSystemService` 里出现，不在 `selectedDomainIds`。课已裁决「不要删工厂、也不要补 `web-domain-system`」。从覆盖尺看：`A:home-web.services` 是否必须把这句「数字可以不等、但不许只改一扇门」写成格子操作定义，否则读者会拿 Skill 原文否决本课？
2. **换票 / 过期重登不在接线板文件。** `createSsoAuth`、`requestRelogin`、`composeAppRuntime` 都是 App 直连 platform。口诀若把组合点收成 `services.ts`，这些边会丢；若收进本格，又和 L-009 抢 `A:platform-auth` / `A:platform-app-runtime`。
3. **`resolve` 的 domainId 边是虚线。** 常量登录路由传 `identity-access`，manifest `domainId` 是 `admin`，查找只认组件键。失败关闭靠缺 key → `undefined` → 登录位回落 `PortalPage`，不是 `unselected-domain`（该错误码在 compose 时抛，resolve 捕获是死分支）。这是 runtime 边，更像 L-009。
4. **认人成功后的存储点。** 认人厅：浏览器 SSO Cookie（本课组合层）。厅堂：`Home-Token`（`session.ts` + 回调 `setToken`）。授权码写入在后端（L-055），不在 `requestAuthorize` 的返回值里。矩阵 SSO 主路径仍 uncovered。问：本格是否只需要「Cookie 与 Token 不共用」这一句所有权，码表存储留给 L-055？

问：Lead 能否凭「`services.ts` 三个 `create*` + sso 五函数 URL/Cookie」把两格 (a) 标 covered，把换票 / resolve / PKCE 全部 defer？还是 `A:home-web.services` 必须包含三扇门操作定义，`A:sso-web.ssoApi` 必须点名 Cookie 写入点，否则 (a) 目的没说完？
